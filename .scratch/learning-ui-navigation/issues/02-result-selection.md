# UI02：用可讀清單選擇資料與成果並保存顯示名稱

狀態：已完成。
阻擋來源：[UI01](01-responsive-loading.md)。
對應決策：Q6、Q16、Q18。
規格：[學習實驗導覽與操作改善](../spec.md)。
索引：[本批工作票](../README.md)。

功能已實作並完成驗收及審查；具體證據與限制如下。

## 要交付的行為

用能直接選取的清單替代各層逐份翻找與默選最近檔案，列出名稱、日期、來源與狀態。使用者可以辨識並改名舊成果，重新開啟後仍選到同一份資料。

## 範圍與界線

本票交付資料與成果的選取及顯示身分；跨來源候選彙整由 UI07 負責。改名僅保存顯示資訊，不改寫研究快照、凍結候選、報告或其驗證身分。

參考位置：`ui/learning_view.py`、`ui/teacher_view.py`、`ui/label_view.py`、`ui/training_view.py`、`ui/group_training_view.py`、`ui/combination_view.py` 及資料／成果保存識別。檔案位置僅供探索定位，不限制合理實作方式。

## 功能驗收與驗證方式

- [x] 資料集、教師先導、教師標記、訓練與組合成果都能從清單直接選取。驗證：建立多份保存資料，透過各入口選擇非最近項目並核對實際來源。
- [x] 舊成果未命名時也有日期與用途構成的可讀名稱。驗證：載入未含顯示名稱的舊資料，檢查清單名稱、來源及狀態；缺少可靠日期時明示缺漏，不虛構日期。
- [x] 改名後重開仍顯示使用者設定的名稱。驗證：從 UI 改名、關閉並重開相同成果。
- [x] 同名成果與改名成果不會選錯研究身分。驗證：兩份成果使用相同名稱，逐份選取並比對保存身分。
- [x] 改名不改變既有研究快照與凍結結果。驗證：改名前後比對原檔內容，並經既有公開載入驗證讀回。
- [x] 重新開啟保留上次明確選擇，不被較新的未完成成果取代。驗證：先選較早完成成果，再新增未完成資料並重開。
- [x] 下游成果的來源關係不會因切換資料而被默默混用。驗證：選取不同資料集及教師條件，確認顯示與實際採用的來源一致。
- [x] 記住的成果失效時提示原選擇不可用並允許改選。驗證：在測試資料中移走原檔後重開，確認未自動套入其他成果。
- [x] 大量及長中文名稱清單仍可查找並選取。驗證：超過一頁的資料，以滾動或分頁操作選取最後項目並檢查畫面。

## 驗證安排

優先沿用公開保存／重開流程與 UI 事件。改名驗證研究身分與檔案內容，不為靜態文字或列表常數新增測試。
共通測試與結案規則見[索引](../README.md#驗收與結案規則)及[專案規範](../../../docs/agents/issue-tracker.md)。

## 人工重現方式（尚未執行）

選一份較早完成的成果，改成易辨識名稱；重開確認仍選到它，再選另一份同名成果核對來源。

## 驗收證據與限制

- `python -m unittest tests.ui.test_saved_selection` 共 13 例通過，以應用程式滑鼠及輸入事件驗證六類清單、舊成果重開、同名身分、損壞／缺失及改選、不同先導與標記來源、長名稱分頁、活動任務及連續任務的來源保護；小資料使用真實保存及公開載入入口。
- 改名群組成果前後比對原快照與凍結設定位元組，並由公開載入入口驗證；名稱與選擇存於專案內 `data/learning-ui.json`，不寫入研究成果。新成果以建立日期命名；舊資料無可靠建立日期時顯示「日期不明」。
- 以 pygame dummy 驅動實際繪製 900×768 長中文清單並檢查，名稱截斷時來源、識別及狀態仍獨立可見；分頁事件選到第十筆。未進行使用者操作驗收或正式長實驗。
- 載入、教師標記、跨頁任務與成果選擇回歸 33 例通過；群組、棋子位置、組合及教師先導回歸 7 例通過。獨立審查發現的資料準備互斥、跨層來源及連續任務問題均已修正並補事件測試，複審未確認其他阻擋問題。

- 整合分支以專案虛擬環境複跑成果選擇、背景載入、跨頁任務、教師標記、群組與棋子位置學習、組合及教師先導回歸，共 40 例通過；獨立複審確認已修正的跨任務問題無其他阻擋。
