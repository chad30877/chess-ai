## 要交付的行為

用能直接選取的清單替代各層逐份翻找與默選最近檔案，列出名稱、日期、來源與狀態。使用者可以辨識並改名舊成果，重新開啟後仍選到同一份資料。

## 範圍與界線

本票交付資料與成果的選取及顯示身分；跨來源候選彙整由 UI07 負責。改名僅保存顯示資訊，不改寫研究快照、凍結候選、報告或其驗證身分。

參考位置：`ui/learning_view.py`、`ui/teacher_view.py`、`ui/label_view.py`、`ui/training_view.py`、`ui/group_training_view.py`、`ui/combination_view.py` 及資料／成果保存識別。檔案位置僅供探索定位，不限制合理實作方式。

## 功能驗收與驗證方式

- [ ] 資料集、教師先導、教師標記、訓練與組合成果都能從清單直接選取。驗證：建立多份保存資料，透過各入口選擇非最近項目並核對實際來源。
- [ ] 舊成果未命名時也有日期與用途構成的可讀名稱。驗證：載入未含顯示名稱的舊資料，檢查清單名稱、來源及狀態；缺少可靠日期時明示缺漏，不虛構日期。
- [ ] 改名後重開仍顯示使用者設定的名稱。驗證：從 UI 改名、關閉並重開相同成果。
- [ ] 同名成果與改名成果不會選錯研究身分。驗證：兩份成果使用相同名稱，逐份選取並比對保存身分。
- [ ] 改名不改變既有研究快照與凍結結果。驗證：改名前後比對原檔內容，並經既有公開載入驗證讀回。
- [ ] 重新開啟保留上次明確選擇，不被較新的未完成成果取代。驗證：先選較早完成成果，再新增未完成資料並重開。
- [ ] 下游成果的來源關係不會因切換資料而被默默混用。驗證：選取不同資料集及教師條件，確認顯示與實際採用的來源一致。
- [ ] 記住的成果失效時提示原選擇不可用並允許改選。驗證：在測試資料中移走原檔後重開，確認未自動套入其他成果。
- [ ] 大量及長中文名稱清單仍可查找並選取。驗證：超過一頁的資料，以滾動或分頁操作選取最後項目並檢查畫面。

## 驗證安排

優先沿用公開保存／重開流程與 UI 事件。改名驗證研究身分與檔案內容，不為靜態文字或列表常數新增測試。
共通測試與結案規則見[索引](../README.md#驗收與結案規則)及[專案規範](../../../docs/agents/issue-tracker.md)。
