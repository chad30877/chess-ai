## 要交付的行為

驗證所有工作票合併後仍能從直接入口使用舊成果、新建學習、跨頁執行、停止重開及比較回放，並在最小與預設視窗保持可操作。更新實際操作文件及本批結案證據。

## 範圍與界線

UI06 與 UI09 的直接依賴閉包涵蓋 UI01～UI09，九票均完成必要驗收後才可開始本票。各票自己的功能驗收不能延後到本票才補做；本票負責跨票整合與文件一致性，不啟動正式長研究。

參考位置：本批已完成 UI 與公開執行入口、`tests/TESTING.md`、`docs/使用者介面.md`、`docs/ML試驗教學.html`、本批索引及 `docs/開發計畫.md`。檔案位置僅供探索定位，不限制合理實作方式。

## 功能驗收與驗證方式

- [ ] 已確認 Q1～Q18 均有完成票與對應驗收證據。驗證：逐條稽核規格、各票勾選、實際測試或操作證據，未通過項保留未勾選。
- [ ] 已有舊成果的使用者能直接從學習實驗進入比較。驗證：以新舊格式及跨來源資料走實際 UI 事件，不先經教師或組合頁。
- [ ] 新建單群組學習到另存與用於對戰的短流程可完成。驗證：小資料真實求解、保存與實際套用設定。
- [ ] 任務跨頁、停止、關閉及重開續跑的整條流程保持同一來源。驗證：教師標記、訓練及比較各做短整合案例並核對保存成果。
- [ ] 較早完成成果不被後來未完成或失效成果取代。驗證：混合來源選擇、改名、重開及失效恢復的跨頁事件流程。
- [ ] 比較結果、設定明細與回放返回維持正確來源。驗證：跨來源候選建立短比較後檢視結果與回放。
- [ ] 900×768 最小視窗中的主操作可讀可用。驗證：實際渲染導覽、進度、錯誤、群組選擇與長清單並操作捲動。
- [ ] 1280×960 預設視窗中的資訊層級清楚。驗證：Agent 畫面檢查位置、階段、任務與結果摘要，詳細資訊不壓過主操作。
- [ ] 相關既有一般批次、真人與回放流程沒有因共用路由或任務變更而退化。驗證：依實際改動範圍跑現有事件整合回歸。
- [ ] 整批必要驗收的限制與未完成項均有如實記錄。驗證：區分自動測試、Agent 實際操作與僅提供人工步驟，必要驗收缺漏不得宣稱結案。
