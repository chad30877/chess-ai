UI04、UI05 已完成；本票已依下列證據驗收。

## 要交付的行為

用同一單群組學習入口勾選五個群組，新建與既有訓練操作分離。舊棋子位置成果仍可開啟及依原條件續跑，結果先呈現摘要及下一步。

## 範圍與界線

新建沿用既有單群組學習規則、三強度候選與共用預算；不新增可調數值，不把多選群組當成聯合訓練。組合維持獨立子頁及既有來源限制。跨來源候選格式轉接由 UI07 負責。

參考位置：`ui/training_view.py`、`ui/group_training_view.py`、`ui/combination_view.py`、`engine/learning/training.py`、`engine/learning/group_training.py`。檔案位置僅供探索定位，不限制合理實作方式。

## 功能驗收與驗證方式

- [x] 新建訓練首次顯示五群組全選。驗證：由新入口建立草稿並檢查可操作選擇與數量。
- [x] 實際保存的訓練群組與勾選一致。驗證：選一組及多組經 UI 開始，核對公開保存快照。
- [x] 零選取時不會啟動訓練。驗證：取消全部勾選後操作開始並確認沒有新任務。
- [x] 各選取群組自動完成既有三強度流程並各自產生候選。驗證：小資料真實求解與保存，核對各組成果及共用預算。
- [x] 既有訓練續跑固定使用原條件。驗證：開啟未完成訓練並續跑，核對原群組與已提交成果。
- [x] 以此建立新訓練使用新選擇且保留原成果。驗證：從舊結果另建不同群組，核對兩份保存身分與原檔。
- [x] 舊獨立棋子位置成果可由合併入口開啟及依實際能力續跑。驗證：舊格式完成與未完成資料各走公開載入及 UI 操作，不要求重訓完整成果。
- [x] 結果摘要顯示群組狀態與學習前後教師誤差。驗證：完成、未完成與缺分層資料的畫面檢查及實際報告對照。
- [x] 權重明細及訓練診斷可按需展開。驗證：從摘要打開詳情並核對對應群組與階段。
- [x] 沒有對戰證據的成果標示尚未比較而非棋力提升。驗證：只提供教師誤差改善報告的 UI 情境。
- [x] 比較、另存設定及用於對戰會使用目前選取的凍結候選。驗證：透過三個操作核對實際候選身分與設定。
- [x] 組合入口仍與單群組操作區分且保留來源相容性檢查。驗證：進入組合及選取不相容來源，核對既有阻擋行為。

## 驗收證據與限制

- `tests.ui.test_group_draft` 以實際滑鼠事件檢查預設全選、零選阻止、一組實際三強度求解及保存、不同群組另建與原成果保留；從跨來源成果另建時恢復原標記。另用公開載入與 UI 續跑舊棋子位置成果。

- `tests.ui.test_group_training` 實際執行五群組、停止並重開續跑，核對已保存候選及結果；`tests.ui.test_combination_training` 檢查組合入口、凍結來源與對戰設定。相關核心求解與任務導覽回歸共 19 項通過；導覽、成果選擇及群組／舊訓練 UI 回歸共 24 項通過；最後執行關閉、導覽、成果選擇回歸 36 項通過。
- 以 SDL dummy 渲染並檢查 900×768 的草稿、完成、未完成與殘局無資料畫面；以實際報告核對分階段數值。這不是使用者手動操作。
