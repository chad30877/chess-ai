# 學習實驗導覽與操作改善：訪談草稿

狀態：訪談中。僅「已確認決策」代表使用者已接受的方向；其餘內容不構成實作授權或完整驗收規格。

## 使用者提出的問題

- 希望顯示目前所在頁面，例如「學習實驗 > 教師先導 > 教師標記」。
- 按下教師標記後會等待一陣子。
- 不理解棋子位置學習的用途。
- 五個單群組難以操作，不知道如何開始。
- 要進入候選比較，必須沿多個頁面一直點下去。

## 已確認決策

### Q1：依操作目的進入

使用者已接受學習實驗首頁先選擇本次操作目的，例如接續學習、比較候選、查看結果及建立新實驗。已有成果的使用者不必為了比較而走過準備頁。具體入口名稱、資料選擇及未滿足前置條件的呈現方式仍待後續訪談。

### Q2：位置與流程進度分開呈現

使用者已接受頂部顯示可點擊、可返回上層的位置路徑，流程進度另外以精簡的階段狀態呈現。路徑不以先前點過的頁面串成假層級；實際頁面層級與階段名稱仍待後續設計。

### Q3：合併單群組學習入口

使用者已接受將棋子位置與五個單群組合併為「評分權重學習」入口。使用者勾選想學習的評分項群組再開始訓練，每個群組各自產生結果；組合訓練另外呈現。合併的是操作入口，不將多個群組的獨立訓練誤當成聯合訓練。群組選擇、預設值、結果呈現及既有單組成果如何開啟仍待細化。

### Q4：直接進入候選與比較紀錄

使用者已接受進入「比較候選」即可看到已有候選並勾選比較對象，同頁提供既有比較紀錄，可接續未完成對局或查看結果，不必經過組合頁。候選來源範圍、比較條件及不同狀態的可用操作仍待細化。

### Q5：載入立即回應並保留返回

使用者已接受點擊教師標記後立即顯示頁面及「載入已保存標記…」，載入期間仍可返回，完成驗證後才開放續跑與學習。其他讀取較慢的頁面採相同行為。此決策只涵蓋讀取期間的回應；已開始執行的教師、訓練或對局任務在離開頁面時如何處理，仍待確認。

## 現況證據

- `ui/learning_view.py`、`ui/teacher_view.py`、`ui/label_view.py` 將資料準備、教師先導及教師標記串接為相鄰頁入口，沒有共用位置路徑。
- `engine/learning/training.py` 的棋子位置學習調整既有位置表的中局與殘局整體倍率，不是重新學習每格數值。
- `engine/learning/group_training.py` 支援任選一到五個群組獨立訓練，包含棋子位置；它依賴完整教師標記，不依賴先完成獨立的棋子位置學習。
- `ui/learning_view.py` 的教師標記動作先呼叫 `labels.open()`，完成才切換頁面；`engine/learning/labeling.py` 會讀取並驗證逐局面記錄。唯讀單次量測目前 5,809 筆保存標記的 `load_labeling()` 約 1.014 秒。此數字不是完整 UI 點擊耗時或冷快取基準，也未證明這是唯一瓶頸。
- 共同開局比較可從群組或組合結果進入；候選盤點則藏在組合頁之後。兩者呈現不同範圍的候選與比較流程，需確認使用者想直達的操作。

## 待釐清

- 實驗與歷史成果選擇、候選來源範圍及前置條件提示。
- 學習群組選擇、參數預設、結果呈現與既有單組成果的開啟方式。
- 比較條件與結果呈現、執行中任務的跨頁導覽、錯誤與恢復操作。
- 具體頁面層級、階段名稱及必要驗收方式。
