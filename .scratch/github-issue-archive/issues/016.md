## 驗收條件

- [x] 以固定局面集合、評分設定及搜尋選項，比較單 worker 與至少兩種多 worker 設定；記錄硬體邏輯處理器數、作業系統與 Python 版本。
- [x] 分別量測冷啟動、程序池重用後的多步搜尋耗時、總節點量，以及包含所有子程序的峰值記憶體。
- [x] 固定總對局工作量比較不同「同時對局數 × 搜尋 worker 數」，包含超額派工；記錄吞吐、單步延遲與記憶體，不藉此新增 CPU 硬限制。
- [x] 量測置換表容量／淘汰參數的取捨，記錄共享或私有表的容量語意、表份數及最終預設值。
- [x] 代表性深度 5 集合呈現可重現的單步等待改善；若未改善，調整方案後再驗收，不能以較高 CPU 占用率代替成果。
- [x] 驗證完成、停止、worker 故障和保存失敗後工作已結束且紀錄可讀；不要求單／多 worker 搜尋結果逐項相同。
- [x] 將基準入口與結論保留為簡潔可重現的實驗資料，更新現況與開發計畫；例行 CI 不使用脆弱的深度 5 耗時斷言。
