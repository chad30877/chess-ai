# 網頁介面：設計規格

狀態：ready-for-agent。決策與理由見[訪談紀錄](../../docs/design/web-ui.md)；工作票見[索引](README.md)。

## 問題

pygame 介面難以使用。輸入欄、選項、清單列和動作都畫成同一種按鈕，文字對不齊，分頁元件也很粗糙；錯誤訊息、統計數字和識別碼混在一起，看不出重點。學習實驗本來是一條依序進行的研究流程，介面卻把它拆成四個並列的分頁，使用者得自己記住做到哪一步、下一步要去哪裡。部分頁面進入時要先等背景讀取和未完成工作的掃描。另外，pygame 只能用固定座標排版，難以美化或調整版面，背景工作也會隨著視窗關閉而停止。

## 解法

改成在本機執行的網頁應用程式：Python 伺服器（FastAPI）提供 API 和 SSE 即時狀態，前端以 Angular 與 Angular Material 製作，依共用的設計規範呈現。功能與現有版本相同，不增不減，但版面依網頁慣例重新設計：側欄導覽，每頁有自己的網址，頂端工作列一律顯示執行中的工作；學習實驗以研究頁的步驟卡呈現流程，資料則改用可搜尋、可排序的清單頁。工作改由伺服器負責，關閉瀏覽器不會停止。全部頁面搬完後移除 pygame。

## 實作決策

### 架構

- **啟動入口**：一個入口同時啟動 FastAPI 伺服器並開啟瀏覽器。伺服器只綁定 127.0.0.1，不做登入；以單一程序執行、不自動重載，並保留 spawn 的程序池所需的主程式保護。
- **前端**：Angular 專案獨立放在一個目錄，使用 standalone 元件與 signals；元件採用 Angular Material。正式使用時，由伺服器提供編譯產物；開發時，用 `ng serve` 把 API 請求代理到伺服器。編譯產物不進版控，Node 套件放在專案內。
- **API 層**：一個新的 Python 套件，只轉接 engine 的執行物件和讀取函式，負責序列化、驗證輸入和處理錯誤，不放運算邏輯。現有的執行物件（批次執行、比較執行、整組比較執行，以及資料集、先導、標記、訓練、群組訓練、組合等 Run）已經提供建構即執行、`snapshot()`、`stop()`、`future` 的共同形狀，直接沿用。
- **工作服務**：伺服器內的工作登錄處取代 pygame 的單一工作欄位和 `active_task`。它負責：
  - 建立工作、查詢、停止
  - 記錄每份工作的來源上下文，供「前往查看」使用
  - 互斥規則：重度工作同時只能有一個；讀取工作可以並行
  - 伺服器關閉時，停止所有工作並等待保存完成

  讀取類工作使用獨立的執行緒池，不和未完成工作的掃描或重度工作排隊。
- **全機重度工作鎖**：以 OS 檔案鎖實作，跨程序有效。搬家期間 pygame 開始重度工作前也要取得這把鎖；取不到時顯示佔用者的說明。既有每個實驗各自的檔案鎖維持不變。
- **即時狀態**：一般操作使用 REST JSON；工作進度、真人對局的 AI 落子和狀態使用 SSE。斷線重連後，先收到一份完整快照，再接續增量。
- **未完成工作掃描**：伺服器啟動時在背景執行，結果快取起來；工作開始或結束時使相關項目失效並重新掃描。首頁和工作列都讀這份快取。
- **選檔服務**：提供以下功能，路徑以伺服器所在的本機為準：
  - 列出資料夾內容
  - 列出可用的磁碟
  - 取得上層資料夾
  - 解析使用者貼上的路徑
  - 依副檔名過濾
- **棋盤**：自寫 SVG 元件，沿用現有的棋子素材。合法走法、升變選項和終局判定都由後端回傳，前端不重新實作棋規。
- **選擇與名稱**：照舊保存在學習介面的選擇檔，保存格式和 pygame 版相容。網頁版接手後，只由網頁寫入。
- **比較候選**：新增「只對 stable 比較」的計畫建立方式：32 條共同開局、深度 3、quiescence 4，不需要先通過快速篩選。既有的快速篩選和雙基準計畫仍可讀取與續跑，但新介面不提供建立它們的入口。
- **效能**：網頁版的讀取不得沿用量測到的重複計算：
  - 共同開局線在同一次請求中只計算一次
  - 比較準備時，每份候選只驗證一次
  - 進入權重學習時，教師標記的驗證結果依檔案變動狀態快取

  不設與機器相關的秒數門檻，只要求記錄實測值。

### 設計規範

- 在第一張畫面工作票之前，先用 design-taste-frontend 的工作畫面流程挑出一個方向，再用 Design 外掛的 design-system 整理成 `docs/設計系統.md`，並轉成 Angular Material 主題。
- 元件規則：
  - 輸入用輸入欄，選項用下拉選單或切換鈕，清單用表格，只有動作做成按鈕
  - 每個區塊最多一個主要按鈕
  - 無法使用的動作要說明原因
  - 錯誤、警告、成功各有色彩與圖示
  - 優先顯示名稱，識別碼收進詳細資訊並可複製
  - 文字靠左對齊，數字靠右對齊
- 密度採緊湊，深淺色跟隨系統。

### 導覽結構

- **側欄**：
  - 對戰（真人對 AI）
  - 對局紀錄（含回放）
  - 批次對戰（一般批次、評分比較、權重實驗）
  - 學習實驗（研究，以及資料、教師評分、候選、比較紀錄四份清單）
- **研究頁**：以一份資料為根，教師標記和權重學習可以切換「目前使用」的版本。步驟卡的狀態只有完成、進行中、未開始、缺少前置四種。

## 測試決策

- 好的測試只驗證外部行為：API 的請求與回應、SSE 事件的順序與內容、保存在磁碟上的結果，以及使用者在畫面上看到和能操作的東西。不斷言內部函式的呼叫次數，也不斷言元件的私有狀態。
- **主要接縫是 HTTP API**：用 FastAPI 的測試客戶端搭配真實的 engine 與暫存資料目錄。凡是牽涉運算的測試，都使用小型合法開局線和短手數上限。現有 pygame 介面測試中的流程斷言，要改寫成 API 測試，包括：
  - 工作互斥
  - 停止與續跑
  - 失效資料不替換來源
  - 過期讀取結果不覆蓋較新的選擇
- **工作鎖**：以兩個程序實測搶鎖。
- **前端單元測試**：只驗證有邏輯的元件，例如棋盤的走法互動、研究頁卡片的狀態映射、選檔對話框的路徑操作。
- **端到端測試**：用 Playwright 跑少量流程，瀏覽器安裝在專案內：
  - 開啟首頁
  - 從對局紀錄回放一局
  - 下一盤短棋到升變
  - 開始並停止一次短比較
  - 在研究頁切換「目前使用」
- 每張畫面工作票都要交出 1280 與 900 兩種寬度的截圖，並附上 design-critique 的結論。
- engine 現有測試本輪不修改，必須持續通過。依賴 pygame 的測試，隨對應頁面的 pygame 版本一起移除。
- 可參考的現有測試：`tests/replay` 的紀錄目錄與比較目錄測試、`tests/test_all_candidates.py` 的候選來源情境、`tests/ui/test_learning_loading.py` 的過期讀取與損壞恢復情境（改寫成 API 測試）、`tests/self_play` 的批次停止與續跑。

## 不在範圍內

- 候選循環賽、共同分數、快速選擇、耗時預估、同時局數設定與低優先權執行，屬於 `candidate-ranking`。
- 新的研究功能、評分特徵或搜尋改進。
- 區網或遠端存取、登入、多使用者。
- 快速篩選和雙基準完整比較的建立入口（舊紀錄仍可讀）。
- 精簡 engine 現有的測試（已列入 future-ideas）。
- 改寫已保存的研究資料格式。
