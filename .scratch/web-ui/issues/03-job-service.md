## 要交付的行為

伺服器持有工作登錄處。重度工作全機同時只跑一個，以跨程序的檔案鎖控制，pygame 開始重度工作前也會取鎖。頂端工作列以 SSE 即時顯示執行中的工作，並可停止；關閉瀏覽器時工作照常繼續，關閉伺服器時則停止並保存。首頁顯示：

- 進行中的工作
- 可續跑的工作（啟動時在背景掃描並快取）
- 最近的研究與對局紀錄
- 三個快速入口

以既有的一般批次作為第一個接入的工作，驗證整條路徑。

## 實作摘要

- **全機鎖**：`engine.sessions.heavy_job` 以作業系統檔案鎖鎖住 `data/.heavy-job.lock`，佔用者的說明寫在旁邊的 `.owner.json`，兩個檔案都已列入 `.gitignore`。`HeavyJobExecutor` 在 submit 時取鎖，取不到就丟出 `HeavyJobBusy`，工作結束後釋放。
- **pygame 端**：
  - 16 處開始重度工作的地方改用 `app.heavy_executor`，涵蓋一般／評分比較批次、資料、教師先導與標記、各種訓練與組合、學習比較。
  - 取不到鎖時，訊息列與視窗標題會顯示佔用者，不會開始工作。
  - 測試注入的執行器不取鎖，避免沒做完的替身工作卡住後續測試。
- **伺服器端**：
  - `api.jobs.JobService` 持有重度工作池與讀取池。`api.home.HomeCache` 在啟動時用讀取池掃描並快取，工作結束後重新掃描；掃描期間，首頁保留上次的結果並標示「更新中」。
  - 未完成工作的掃描從 `ui/unfinished_tasks.py` 搬到 `engine.learning.unfinished`，pygame 介面沿用這份實作。
- **API**：
  - `GET /api/home`
  - `GET /api/jobs`
  - `GET /api/jobs/events`（SSE）
  - `POST /api/jobs/{id}/{stop|pause|resume}`
  - `POST /api/batches/general`
- **前端**：`JobsStore` 以 EventSource 接收工作狀態，工作列放在框架的頂端列。首頁含四區內容與三個入口。

## 驗收證據與限制

- **API 測試**：`python -m unittest tests.api.test_jobs tests.api.test_server tests.ui.test_heavy_job_lock` 共 18 例通過，涵蓋：
  - 子程序持鎖時，主程序取鎖失敗並讀到佔用者「pygame 介面：教師標記」；子程序結束後即可取得
  - 執行器在工作完成後釋放鎖
  - 第二個批次回 409，並附上佔用者資訊
  - 停止後保留已保存的局，且釋放鎖
  - `shutdown` 停止工作，manifest 標為 stopped
  - SSE 先送 `[]` 的完整快照，再送變更
  - 重度工作執行中，首頁掃描仍能完成
  - 首頁列出最近的研究名稱與無法讀取的整組比較，工作結束後重新掃描並出現新紀錄
  - pygame 在全機鎖被網頁佔用時不開始工作，並顯示佔用者
- **完整回歸**：`python -m unittest discover -s tests -t .` 共 573 例。第一次有 1 例錯誤：`tests/ui/test_learning_close.py` 仍修補舊位置的 `ui.unfinished_tasks.comparison_report`。改為修補 `engine.learning.unfinished.comparison_report` 後，重跑該檔 18 例通過，斷言不變。
- **前端單元測試**：`npx ng test --watch=false` 共 7 例通過。工作列涵蓋：無工作、進度與停止請求、已結束的工作不列出、斷線提示。
- **實際操作**（8643 埠，真實資料）：
  - 以 API 開始批次後，工作列與首頁即時顯示「已保存 2 / 4 局」，第二個批次回 409。
  - 在工作列實際按下暫停、繼續、停止；停止的批次 `20261104_0004` 保留 3 局並標為 stopped。
  - 工作結束後，首頁自動出現新紀錄。
  - 首頁在 1280 淺色、900 深色、390 寬度下截圖檢查；taste 量測 0 FAIL，剩下的 1 個 WARN 是圖示字型被算成字體。
- **關閉伺服器實測**：以子程序啟動伺服器並保持一條 SSE 連線，開始 5 局的批次後送出 CTRL_BREAK。伺服器在 3.2 秒內結束，manifest 為 stopped，已保存 3 局。
- **真實資料的掃描耗時**：未完成工作的掃描單獨執行為 3.6 秒，最近紀錄為 0.9 秒；與另一次掃描同時執行時曾達 47 秒。這段時間都在背景，首頁不會等待。
- **限制**：
  - SSE 連線不會自行結束，關閉伺服器時要等 uvicorn 的 3 秒寬限，之後才強制中斷。終端機會印出 CancelledError，結束碼為 3，不影響保存。
  - pygame 若在工作物件建構時、提交前就已寫入檔案（例如資料準備先建立目錄），被拒時可能留下空目錄。
  - 實際操作時在 `data/batches` 新增了 `20261104_0002`～`0004` 三批測試批次；`20261104_0001` 是既有測試套件寫入的。這些都不進版控。
  - 8642 埠當時被使用者驗收 W02 時啟動的伺服器佔用，所以實測改用 8643 埠。
