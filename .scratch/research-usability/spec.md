# 規格：研究前的環境準備、教師並行與操作改善

狀態：實作中；使用者已於 2026-10-25 確認測試入口。不發布 GitHub。

## 問題陳述

使用者已有可操作的評分權重學習流程，但在新環境取得專案與資源時，README 仍依賴原電腦配置且混入大量歷史。教師先導要手打 Stockfish 路徑、固定單程序逐局面分析，且無法用兩種節點預算的量測判斷後續標記耗時。隨著評分設定檔增加，逐次點擊切換難以找到指定群組組合；棋盤缺少最後一手標示，真人模式也無法清楚辨識開局庫與搜尋狀態。

## 解決方案

將 README 整理為假設已有 Git 的 Windows CMD 操作入口，以現用資源提供可替換的下載範例。先導預填專案內 Stockfish 範例位置並提供檔案選擇器；讓使用者設定同時分析局面數，以多個單執行緒 Stockfish 完成先導與教師標記，並從相同並行條件的先導實測估算兩種預算的後續標記耗時。

真人與回放棋盤以透明綠標出最後一手造成的全部變動格。各評分設定入口共用獨立選擇小視窗，以名稱及實際啟用群組查找，並支援候選多選。真人模式區分開局庫、搜尋及其他狀態；一般批次只清楚表達開局步數的計數方式。

## 實作決策

### 環境準備與教師選取

- README 假設 Git 已安裝，不增加 Git 安裝教學，也不列全新環境實際部署驗收。CMD 為指令主體；提交身分設定放在開發用途，細節連到既有文件。
- 下載範例沿用現用 Stockfish 19、Lichess 月份棋譜及 TSV 開局庫。標明範例與支援格式，不承諾任意引擎版本或任意開局庫格式皆可使用；已隨 Git 提供的開局庫下載定位為取得或修復。
- 新先導預設路徑相對專案位置解析；重開既有先導優先顯示其保存條件。選檔取消不改原值，選檔成功後仍沿用既有教師啟動與身分檢查。

### 並行與估時

- workers 定義為同時分析不同局面的 Stockfish 程序數；每個程序的 Threads 固定為 1。這與對戰的搜尋 worker、同時對局數分開。
- 新先導預設 workers 為可用 CPU 數與 4 的較小值，至少為 1；使用者可調整正整數，實際工作少於設定值時不建立多餘工作。
- 先導與教師標記共同使用有界並行的教師執行能力，保留 UCI 教師邊界、每局面完整歷史及搜尋前重設。程序可重用，但局面間不可混用搜尋狀態；保存與摘要不能因完成順序不同而串錯局面。
- workers 隨先導快照、預算選擇與標記條件保存並凍結。修改 workers 建立新先導，後續標記繼承該條件；缺少 workers 的既有快照按原單程序條件處理，不重寫既有身分或成果。
- 先導仍限訓練組固定最多 100 局面及兩種節點預算；預算選擇維持完成後凍結。先導停止保留已提交結果，不把未完成量測當成可選定預算。
- 教師標記沿用逐局面提交、失敗記錄、完整標記閘門及實驗互斥鎖。停止、關閉或失敗後清理程序；重開續跑以已提交記錄為準，只補未完成或失敗局面。
- 每次執行共用一個八小時期限，不按 workers 重置、不自動重啟。維持教師版本、預算、篩選及歷史相容性檢查。
- 先導需能分別取得兩種預算在相同 workers 下的實際整批經過時間及完成數。不得用各程序分析秒數加總冒充整批時間，也不得將單程序耗時直接除以 workers。
- 預估以各預算實測吞吐與可重用先導結果扣除後的待標記局面數計算，包含後續會被篩除但仍需分析的局面。預估對象是後續教師標記，不含訓練及對戰；不足量依實際局面數計算。
- 必要量測需保存以供重開；零完成數、無可用時間或舊資料缺少足夠量測時顯示無法估計，不產生虛假的零秒或精確值。並行票先交付可保存的分預算實測時間，估時票接入預估與畫面。

### 棋盤、設定與開局狀態

- 最後一手標示共用棋盤與既有走棋歷史，以最後一手前後棋子變動格判定：一般走棋兩格、易位四格、吃過路兵三格；無歷史不猜測。回放倒退後標示造成目前局面的最後一手。
- 色塊為透明綠，與選取框及合法走法提示共存；維持翻轉、縮放及原有走棋互動。
- 設定選擇採應用程式內獨立小視窗，所有既有入口共用。名稱搜尋配合五群組勾選：預設結果須同時包含所選群組，「僅此組合」則不能有額外群組；未篩選可看全部並找到純子力。
- 群組依設定中實際啟用的評分項判定，任一項啟用即可屬於該群組；子力與分階段開關不當成五群組之一。不得依檔名推斷是否為學習成果，不為組合預建固定分類或改動評分設定檔格式。
- 單選入口確認後套用；比較候選支援多選、去重並沿用基準排除規則。取消保持原選擇，另存後重新開啟可看到新設定；損壞或無法讀取的設定不能被靜默當作有效設定套用。
- 真人模式由實際開局政策及搜尋工作狀態呈現庫內或 AI 思考中，保留首次離庫後不再回庫。真人回合、等待間隔、暫停、終局及錯誤不能被誤標成搜尋；未使用開局庫的策略不得宣稱正在用庫選步。
- 一般批次不新增開局狀態顯示，只清楚表達開局最多步數以任一方落子一次計一步。比較模式沿用固定共同開局線長度，不擴充研究條件。

## 測試決策

- 主要入口沿用真實應用程式事件整合測試：操作選檔、先導、預算選擇、標記停止重開、設定選擇、真人及回放，斷言實際選定設定、棋盤狀態與保存結果；不測內部函式呼叫次數、靜態文案或常數。
- 教師程序是必要的外部邊界，沿用既有可控制 UCI 程序替身，驗證多局面確實重疊執行、並行上限、亂序完成不串資料、停止清理、失敗重試與舊資料續跑。時間與檔案故障可控制，不等待真實八小時。
- 原生檔案選擇器只在作業系統選檔回傳邊界提供可控制結果，選取後仍走真實應用程式驗證與啟動流程；另由 Agent 實際選檔短流程驗證整合。
- 少量公開教師執行及載入入口測試保護保存、互斥、凍結及續跑契約；估時用可核對的資料與經過時間驗證數量、可重用記錄及並行吞吐，不直接測內部排程容器。
- 沿用真人、回放及設定比較的事件測試，驗證特殊走棋、倒退跳步、翻轉縮放、多群組包含／精確篩選、多候選及實際套用設定。必要畫面檢查確認綠色色塊與提示可讀，不用整張螢幕像素雜湊取代行為驗證。
- 既有教師先導、教師標記、真人開局及設定選取測試提供先例；既有應用程式事件驅動器與可控制執行器優先重用，不新增通用測試框架或大重構。
- 並行交付補真實 Stockfish 小批次操作證據，確認多程序、停止及續跑；不設機器相關的加速倍率門檻，不重啟已取消的 Threads 評估。
- README 以文件檢閱確認 CMD 語法、來源、可替換範例及既有操作一致性，不新增靜態文字測試、不要求乾淨電腦驗收。人工重現說明與必要驗收分開。

## 不在本規格範圍

- 正式 500 盤研究的重跑、全套候選研究、完整每候選每基準 64 局對戰，以及棋力提升證明。
- 新搜尋演算法、新評分特徵、全群組組合自動研究、研究平台及自動接續多個八小時。
- 批次開局狀態顯示、修改比較模式共同開局線長度。
- 設定檔收藏、自訂分類、重新命名、刪除、來源管理及對局紀錄搜尋。
- Stockfish 全機自動搜尋與下載管理、任意新資料格式的匯入支援、Git 安裝教學及全新環境驗收。
