# R03：由先導預估兩種節點預算的後續標記耗時

狀態：已完成實作與必要驗收；本機結案，不發布 GitHub。

## 父規格

本批本機規格「研究前的環境準備、教師並行與操作改善」。

## 建置內容

完成先導後，使用者在選擇預算前即可比較 50,000 與 200,000 節點各自的後續標記預估時間。預估採同 workers 的實際量測與尚需分析的局面數，並能保存重開；只涵蓋教師標記，不擴充為訓練或對戰估時。

## 必要驗收

- [x] UI 在選定預算前並列兩種預算各自的後續標記預估；以完成先導後的實際事件流程驗證。
- [x] 預估使用各預算實測整批經過時間及完成數，不將單 worker 時間除以 workers；以可手算的並行量測資料驗證。
- [x] 待標記數扣除同條件可重用的先導記錄；以可重用與不可重用記錄混合的案例驗證。
- [x] 仍需教師分析才會被篩除的局面保留於待標記工作量；以篩除條件案例驗證。
- [x] 少於 100 個先導局面時使用實際完成數；以不足量資料整合案例驗證。
- [x] 無完成量、無可用時間或舊先導缺必要量測時顯示無法估計，不輸出虛假時間；以缺資料案例驗證。
- [x] 重開先導可取得相同條件與量測的預估，不重跑教師；以保存、重開及結果比對驗證。
- [x] UI 清楚區分實測耗時、預估耗時及其節點條件，選擇後仍凍結正確預算；以事件流程與必要畫面檢查驗證。

## 人工重現方式（非額外驗收）

完成先導後比較兩種預算的實測與預估，選定其中一個，重開確認條件與預估仍可追溯。

## 驗收證據（2026-10-25）

- `tests/test_labeling_estimates.py`：真實公開先導／載入流程配合可控制時鐘，60 個局面、2 workers 的兩種整批量測為 60／180 秒；96 個總局面扣掉 60 個可重用結果，預估為 36／108 秒。此案例不用固定 100 作分母，也不再除以 workers。
- 同檔混合案例破壞兩筆 50k 紀錄的歷史及評分政策，預估只扣除 58 筆，剩餘 38 筆；真正建立標記得到相同工作量。所有教師結果均為需篩除的將死分數，仍先分析尚缺的 38 筆，完成後篩除總量 96，未錯誤把待分析量歸零。
- 同檔驗證缺少整批量測、完成量為零、時間為零／空值／非有限值、workers 不符及來源身份改變均不輸出虛假預估。移除教師測試執行檔後仍能載入相同估時，沒有重新啟動教師。
- `tests/ui/test_labeling_estimates.py`：事件流程完成先導後、選擇前已有兩個預估；選定 200k 後關閉重開，量測與估時相同，實際新標記仍使用 200k 與相同待標記量。
- 教師相關整組回歸涵蓋 29 項；其中 28 項首次通過，外部事件順序案例發現 Windows `monotonic` 時間戳精度不足，改用高解析度 `perf_counter` 記錄程序觀測。修正後執行 `python -m unittest tests.test_teacher_parallel tests.test_labeling_estimates tests.ui.test_labeling_estimates -v`，9 項全部通過；其餘 20 項已在原回歸通過。
- [真實 Stockfish 紀錄](../evidence/r03-estimates.json)：隔離資料 96 局面、2 workers，先導各完成 60 局面；50k／200k 整批 2.219／7.688 秒，待標記 36 局面的預估為 1.3314／4.6128 秒。已透過實際 UI 事件選定 200k 並重開，比對估時保持一致；這是軟體短流程，不是正式研究或估時準確度保證。
- Agent 已檢視[選預算前畫面](../evidence/r03-pilot-estimates.png)：兩列節點、實測、後續標記預估及篩除量清楚可讀；保存的實測程序數與建立新先導的輸入分開呈現。[缺量測畫面](../evidence/r03-legacy-no-estimate.png)使用移除新量測欄位的隔離副本，兩種預算均顯示無法估計，未拿程序分析秒數加總充當整批時間。
- 已更新既有離線教學及測試導覽；總索引與開發計畫由整合分支統一整理。
