# 規格 B：可續跑的評分權重比較介面

## 問題陳述

目前已有基準對多候選、共同搜尋條件與交換黑白的比較引擎，但使用者仍須手動複製設定檔，難以比較多個權重的組合。既有 UI 候選選擇最多七份，無法涵蓋兩個參數各三值的九組實驗；長時間比較也尚未支援關閉程式後續跑。

## 解法

提供從基準設定選擇已啟用權重、輸入數值或相對基準百分比、預覽組合，到執行比較、排序結果、回放及另存設定的完整流程。每個實驗保存不可變的實際條件與進度，停止或關閉後能接續未完成工作。

## 使用者故事

1. 身為調參使用者，我希望選定基準設定，以便所有候選都有共同參照。
2. 身為使用者，我希望只調已啟用評分項，以免改權重時暗中改變評分項集合。
3. 身為使用者，我希望直接輸入多個值，以便比較自己指定的候選。
4. 身為使用者，我希望用起點、終點與間隔產生值，以便避免大量重複輸入。
5. 身為使用者，我希望用相對基準百分比操作，以便理解每次增減幅度。
6. 身為使用者，我希望同時看到實際權重，以便確認百分比最後套用的數值。
7. 身為使用者，我希望基準為零時仍能設定實際值，以便研究原先沒有貢獻的已啟用項目。
8. 身為使用者，我希望比較多參數的所有選定組合，以便觀察搭配效果。
9. 身為使用者，我希望先看到候選數與對局數，以便評估實驗規模。
10. 身為使用者，我希望重複或未改變的候選被明確辨識，以免浪費對局時間。
11. 身為使用者，我希望預覽與實際對戰使用同一份設定，以便結果可重現。
12. 身為比較者，我希望各候選與基準使用共同搜尋條件和開局、交換黑白，以便公平比較。
13. 身為使用者，我希望每局完成就保存，以免必須等待整個實驗結束才取得成果。
14. 身為使用者，我希望看到勝和敗、得分率與完成樣本數，以便判斷結果的限制。
15. 身為使用者，我希望未完成棋局不被當作和棋，以免統計失真。
16. 身為使用者，我希望排序結果並查看參數差異，以便挑選值得再驗證的候選。
17. 身為使用者，我希望從候選結果開啟棋譜，以便觀察實際選步。
18. 身為使用者，我希望另存候選為評分設定檔，以便真人對戰或下輪比較使用。
19. 身為長時間實驗使用者，我希望停止、關閉或意外退出後續跑，以免完成的成果作廢。
20. 身為使用者，我希望續跑不重複計入棋局，也不偷偷改條件，以便維持結果可信度。
21. 身為舊紀錄使用者，我希望原有比較結果仍能讀取，以便保留既有資料。
22. 身為未來 ML 使用者，我希望學習出的設定能作為候選載入，以便沿用同一套驗證流程。

## 實作決策

- 沿用既有評分比較、背景執行、逐局保存與紀錄讀取流程；新增一個實驗定義，串接候選生成、比較、結果與續跑，不另做第二套對戰引擎。
- 第一版固定棋子價值、評分項開關、階段模型與搜尋條件。可調欄位為已啟用的 PST 倍率及現有位置評分項權重；階段混合啟用時中局與殘局權重可分別選取，停用時不產生無效的殘局調整。此規則是 UI 比較範圍，不替下一批 ML 決定訓練策略。
- 數值清單與起點／終點／正間隔兩種輸入都支援。範圍按間隔產生不超過終點的數值，只有對齊間隔時才包含終點；拒絕非有限數、非法負值、倒置範圍及零間隔。
- 相對基準百分比以該次不可變基準權重為分母，100% 等於基準，150% 為其 1.5 倍，不要求各項合計 100%。基準為零時停用百分比輸入並提供實際值。切換表示模式不可偷偷改變候選實際值。
- 多參數形成笛卡兒積，按穩定順序產生候選；兩參數各三值應得到九組，再依完整有效設定去重，移除與基準相同的候選並顯示數量變化。顯示名稱不作唯一識別。
- 預覽包含基準快照、每個候選實際差異、有效候選數、局面數、重複次數與計畫對局數。基準／參數／搜尋條件變更會使舊預覽失效；執行只能使用已預覽的同一份定義。
- 計畫對局數為有效候選數 × 起始局面數 × 重複次數 × 2。支援九組及更多候選的分頁或捲動，不能保留七份的顯示／執行限制或靜默截斷；大型輸入先計數，避免同步展開使介面失去回應。遇資源限制須在啟動前清楚回報。
- 保存完整基準／候選設定、候選生成規則、共同搜尋／開局／種子／棋規／手數限制及程式／特徵版本。穩定的候選與棋局工作識別是比較、回放及續跑的共同依據。
- 所有候選使用相同搜尋條件，各自對基準以同起始局面交換黑白，不是候選彼此總循環。沿用既有配對種子政策；不把確定性棋局重複當成額外獨立棋力證據。
- 結果表呈現參數差異、勝和敗、完整配對得分率、完整配對數、未完成數與對局耗時。得分率為完整配對中的勝得 1、和得 0.5 除以其中棋局數；無完整配對時顯示無資料，不能填 0%。孤立完成棋局可回放，但尚不計入配對得分率。
- 排序只改變展示順序；未完成與無資料須可辨識，不自動宣告最強。對局耗時加總與實驗經過時間分開定義，不把並行工作時間加總誤稱為使用者等待時間。
- 另存設定使用候選的實際快照而非重新套用百分比，不覆寫基準；保存後可從現有真人對戰及比較入口載入。既有紀錄保持可讀，缺欄位不補造統計。
- 實驗可執行數小時或過夜。已提交完成的棋局不可重跑或重複計數；未完成／被中斷的工作可從該局起點重跑，保留已存在的中斷紀錄並與有效完成結果區分。正常達到手數上限的截斷是既定工作結果，不在每次續跑無限重跑，也不列為和棋。
- 續跑讀取已保存的實驗定義，不從可能已修改的設定檔重建；條件不相容時拒絕混接並提示建立新實驗。同一實驗不可同時由兩個執行者續跑。
- 保存順序與恢復流程須能處理棋局已保存、進度尚未更新的中斷點；重開後依穩定工作識別恢復一致統計，不能重複加總或覆寫完整棋局。已完成實驗的續跑操作不再派工。

## 測試決策

- 主要入口為應用程式事件／比較執行操作，走到真實實驗快照、棋局保存與重新讀取；沿用現有 dummy UI、可控背景工作及比較整合測試。
- 先驗證單參數選擇到棋局結果的完整流程，再驗證九組候選、實際值與百分比等價輸入、範圍邊界、零基準、停用項及重複候選。
- 高層測試核對預覽與對戰實際快照一致、基準不被修改、共同條件及交換黑白保持、配對得分率分母正確。不得僅測按鈕文字、欄位存在或 helper 有被呼叫。
- 結果排序後仍開啟正確候選棋譜、另存正確設定；保存再載入數值與開關一致，舊比較紀錄可讀。
- 續跑測試從完整完成一局、半組配對、保存後未更新進度、執行中故障等情況重建應用狀態，驗證不漏局、不重複計數、不混設定及不殘留工作程序；至少一項測試跨新程序驗證。
- 沿用真實多程序的少量比較情境確認停止與關閉清理，不以大量長局當單元測試。短測只驗證流程，正式棋力試驗使用另留局面。

## 不在範圍內

ML 訓練與教師標記介面、搜尋參數自動調優、評分項開關的組合搜尋、新評分項、權重合計 100% 的偏好配置、自動宣告最強或 Elo 保證、固定時間對戰比較、進行到一半棋局的逐手斷點續下、雲端執行。

## 補充說明

人工驗收選兩個已啟用權重各三個非基準值，預覽九組候選後執行短局；核對結果與另存設定。另以能完成配對的短測試局面，保存一局後停止並重開，接續剩餘工作且原局只計一次。短局截斷必須顯示未完成，不能當作和棋。
