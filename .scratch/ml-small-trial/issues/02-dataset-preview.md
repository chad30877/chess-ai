# M02：從 UI 建立可重現的棋譜資料分組與局面預覽

## 父規格

[規格：可操作、可續跑的 ML 小規模權重試驗與共同開局驗證](https://github.com/chad30877/chess-ai/issues/26)

## 要建置的內容

使用者可選取／取得固定來源棋譜，建立學習實驗，預覽訓練、驗證、測試的實際樣本及排除數，保存後重新開啟查看。這個資料準備切片獨立於設定預設及教師程序。

## 驗收條件

- [x] UI 提供 Lichess 2013 年 1 月標準棋資料來源與本機檔案入口；取得方式、CC0 授權、來源雜湊、種子及處理版本保存於不可變快照。大檔串流處理，錯誤可見，背景處理不凍結 UI。
- [x] 去重棋譜後抽 500 盤，先按整盤分為 350／75／75，再每盤最多抽 12 局面；略過前 8 手，兼顧棋局階段，保留完整合法歷史。來源不足須明確報告，不重複補足。
- [x] 同組重複局面只留一份，跨組重複從所有組排除；局面身份使用盤面、輪到方、易位與有效吃過路兵，不以回合數區別。
- [x] 教師前先排除已終局及受將局面，保存排除原因；UI 顯示各分組盤數、局面數、階段分布與篩除統計，接受總量不足 6,000。

- [x] 高層資料建立／保存／重開測試以小型棋譜驗證確定性、整盤隔離、跨組重複、有效吃過路兵身份及損壞輸入；測試不依賴下載完整公開檔案。
- [x] 由 Agent 透過應用程式 UI 事件整合測試或實際操作，建立並重開資料預覽。
- [x] 更新簡短測試說明及目前開發計畫，保存驗證證據與限制。
- [x] 完成實作與文件的繁體中文 Git commit。

## 執行與結案

一般 `/implement` 由 Agent 完成必要驗證並記錄證據，接著依專案 tracker 流程同步 GitHub 與本機票、索引及開發計畫，提交並關閉本票，最後讀回核對。供使用者重現的操作方式不是另一次必要人工驗收；不例行等待使用者操作或再次同意關票。真實失敗或缺少必要資源時先修復，無法完成才保留未勾選、開啟狀態並說明阻礙。

軟體驗收使用足以涵蓋行為的短流程；八小時停止以可控制時鐘驗證。正式完整資料與長時間對戰由使用者於交付後分次執行，不能把短流程結果宣稱為完整研究或棋力提升。
