# M03：從 UI 量測 Stockfish 教師預算並保存選擇

## 父規格

[規格：可操作、可續跑的 ML 小規模權重試驗與共同開局驗證](https://github.com/chad30877/chess-ai/issues/26)

## 要建置的內容

使用者選擇固定 Stockfish 19，對訓練來源中的約 100 個局面量測兩個節點預算，查看耗時與分數差異，再選定正式標記條件。提供真正可操作的教師準備流程。

## 驗收條件

- [x] UI 可選教師執行檔並檢查引擎識別，保存版本、雜湊、UCI 選項、快取初始化政策及來源／授權資訊；不靜默替換版本。
- [x] 僅從訓練來源固定抽取約 100 局面，分別使用 50,000／200,000 節點，保存完整歷史、原始分數／視角、白方分數、最佳手與耗時；不使用測試資料決定預算。
- [x] 顯示兩種預算的耗時、有效分數差異及無法比較／將被篩除數；由使用者選定預算後保存不可變條件，不宣稱節點數保證品質。
- [x] UCI 通訊與棋局狀態重設有一致政策，選項與資料身份相同才可重用既有標記；教師不啟用殘局資料庫。
- [x] UI 顯示進度、停止及缺少執行檔、引擎崩潰、逾時、非法走法等錯誤；停止後釋放程序，不把不完整結果當成功。先導執行也受八小時上限約束。
- [x] 以可控制 UCI 測試程序，從公開執行入口驗證白方視角、歷史、預算選擇、錯誤與取消；真實 Stockfish 做獨立短先導，不放入日常測試。
- [x] 由 Agent 從 UI 入口完成真實 Stockfish 先導並重開已保存選擇，記錄量測結果；不以教師替身取代真實先導。
- [x] 更新簡短測試說明及目前開發計畫，保存驗證證據與限制。
- [x] 完成實作與文件的繁體中文 Git commit。

## 執行與結案

一般 `/implement` 由 Agent 完成必要驗證並記錄證據，接著依專案 tracker 流程同步 GitHub 與本機票、索引及開發計畫，提交並關閉本票，最後讀回核對。供使用者重現的操作方式不是另一次必要人工驗收；不例行等待使用者操作或再次同意關票。真實失敗或缺少必要資源時先修復，無法完成才保留未勾選、開啟狀態並說明阻礙。

軟體驗收使用足以涵蓋行為的短流程；八小時停止以可控制時鐘驗證。正式完整資料與長時間對戰由使用者於交付後分次執行，不能把短流程結果宣稱為完整研究或棋力提升。
