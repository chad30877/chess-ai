# M08：一般與真人對戰可選開局庫並在離庫後搜尋

## 父規格

[規格：可操作、可續跑的 ML 小規模權重試驗與共同開局驗證](https://github.com/chad30877/chess-ai/issues/26)

## 要建置的內容

在一般對戰與真人對 AI 的 Alpha-Beta 路徑提供開局庫開關、手數上限與可重現保存；收錄走法用完後繼續正常搜尋。不依賴 ML 即可單獨驗收。

## 驗收條件

- [x] 取得並固定 Lichess 具名開局資料版本、雜湊及 CC0 授權，驗證完整合法序列；UI 可選擇啟用，資料缺失／損壞可見，不靜默換來源。
- [x] 從目前局面不同合法收錄走法等機率選擇；同一走法出現於多個開局名稱不增加權重，不假造勝率資料。
- [x] 預設最多 12 手、UI 可調；首次查無走法或達上限後該局永久離庫，之後使用 Alpha-Beta。真人落子也更新離庫狀態，新局才重置。
- [x] 保存來源、種子、實際開局走法與離庫狀態，搜尋棋盤保持完整歷史，記錄可回放；未啟用開局庫時保持既有行為。
- [x] 單局及一般批次使用相同政策；停止或重新開始不讓舊工作結果落入新局，保持既有逐手進度。
- [x] 從對戰／UI 入口驗證去重、種子重現、手數界線、離庫後不回庫、真人偏離、保存回放與停止；不以少量抽樣頻率硬斷言機率。
- [x] 透過 UI 事件整合測試或實際操作，驗證開啟開局庫並超過上限後接續搜尋；既有使用者操作確認可作為證據。
- [x] 更新簡短測試說明及目前開發計畫，保存驗證證據與限制。
- [x] 完成實作與文件的繁體中文 Git commit。

## 執行與結案

一般 `/implement` 由 Agent 完成必要驗證並記錄證據，接著依專案 tracker 流程同步 GitHub 與本機票、索引及開發計畫，提交並關閉本票，最後讀回核對。供使用者重現的操作方式不是另一次必要人工驗收；不例行等待使用者操作或再次同意關票。真實失敗或缺少必要資源時先修復，無法完成才保留未勾選、開啟狀態並說明阻礙。

軟體驗收使用足以涵蓋行為的短流程；八小時停止以可控制時鐘驗證。正式完整資料與長時間對戰由使用者於交付後分次執行，不能把短流程結果宣稱為完整研究或棋力提升。
