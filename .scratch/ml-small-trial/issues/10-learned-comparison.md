# M10：學習結果接入深度三共同開局驗證與研究報告

## 父規格

[規格：可操作、可續跑的 ML 小規模權重試驗與共同開局驗證](https://github.com/chad30877/chess-ai/issues/26)

## 要建置的內容

使用者從學習結果選擇候選，預覽完整對戰條件後送入共同開局比較，查看逐開局對戰結果、回放及獨立於教師誤差的研究結論。單群組先可使用，組合輸出沿用相同設定契約。

## 驗收條件

- [x] 結果入口可選原始／學習候選與純子力主基準，另以既有 stable 作參考比較；保存來源實驗及完整設定，直接組合／聯合訓練可透過相同合法設定契約接入。
- [x] 預覽並固定深度 3／q4、同時 4 局、每局 1 搜尋 worker、TT 4,096 筆，雙方一致。現有判和政策與手數上限保存於快照，不改成深度 5。
- [x] 使用 32 條共同線，每候選對每個選定基準 64 局；額外 stable 比較明確增加總工作量，各基準統計分開，不誤用分母。
- [x] 保留逐手進度、逐場保存、完整配對統計、停止／重開續跑、回放與另存；原始／學習設定身份不可因排序或顯示名稱混淆。

- [x] 高層學習結果到比較、保存及重開測試驗證設定相同、額外參考工作量、候選來源及統計；使用小型合法開局檢查流程，不在日常測試跑完整 64 局。
- [x] 由 Agent 透過 UI 事件整合測試或實際操作，從學習結果進入短比較並查看回放；提供完整對戰可分次執行的操作方式。
- [x] 更新簡短測試說明及目前開發計畫，保存驗證證據與限制。

## 執行與結案

一般 `/implement` 由 Agent 完成必要驗證並記錄證據，接著依專案 tracker 流程同步 GitHub 與本機票、索引及開發計畫，提交並關閉本票，最後讀回核對。供使用者重現的操作方式不是另一次必要人工驗收；不例行等待使用者操作或再次同意關票。真實失敗或缺少必要資源時先修復，無法完成才保留未勾選、開啟狀態並說明阻礙。

軟體驗收使用足以涵蓋行為的短流程；八小時停止以可控制時鐘驗證。正式完整資料與長時間對戰由使用者於交付後分次執行，不能把短流程結果宣稱為完整研究或棋力提升。
