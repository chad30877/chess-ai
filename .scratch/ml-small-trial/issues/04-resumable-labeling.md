# M04：逐局面教師標記、篩選與八小時停止續跑

## 父規格

[規格：可操作、可續跑的 ML 小規模權重試驗與共同開局驗證](https://github.com/chad30877/chess-ai/issues/26)

## 要建置的內容

使用者對已準備資料執行完整教師標記，看到保留與排除原因，能停止、關閉及續跑，完成可供學習使用的資料集。

## 驗收條件

- [x] 使用已凍結教師設定標記所有分組，逐局面提交原始輸出及轉換結果；相容先導標記可重用，不同預算或條件不得混用。
- [x] 篩除 mate、最佳手吃子／升變、bound-only 與殘局資料庫特殊分數；保存各原因與計數，不把未知輸出當一般 cp。另合併資料階段的排除統計。
- [x] 每次執行共享最多八小時，時間到或手動停止保存並退出，不自動重啟；UI 顯示完成、剩餘、失敗／需重跑與有效分組分布。
- [x] 重新開啟後只處理未完成工作，已成功標記不重複計入；提交後摘要落後可恢復。未完成或失敗局面可以重試，同實驗禁止同時執行兩份工作。
- [x] 修改教師或篩選條件建立新快照；部分資料不能冒充完成資料進入正式學習，實際不足額明確顯示。
- [x] 以高層執行／保存／重開流程及可控制時鐘驗證上限、停止、崩潰、保存失敗、重試及去重；保留 UCI 外部替身邊界，其餘使用真實保存邏輯。
- [x] 由 Agent 透過 UI 事件整合測試或實際操作，中途停止、關閉、重開續跑並核對已完成量。
- [x] 更新簡短測試說明及目前開發計畫，保存驗證證據與限制。
- [x] 完成實作與文件的繁體中文 Git commit。

## 執行與結案

一般 `/implement` 由 Agent 完成必要驗證並記錄證據，接著依專案 tracker 流程同步 GitHub 與本機票、索引及開發計畫，提交並關閉本票，最後讀回核對。供使用者重現的操作方式不是另一次必要人工驗收；不例行等待使用者操作或再次同意關票。真實失敗或缺少必要資源時先修復，無法完成才保留未勾選、開啟狀態並說明阻礙。

軟體驗收使用足以涵蓋行為的短流程；八小時停止以可控制時鐘驗證。正式完整資料與長時間對戰由使用者於交付後分次執行，不能把短流程結果宣稱為完整研究或棋力提升。

- `create_labeling` 凍結來源副本、教師完整身份、已選節點預算、評分選取政策與篩選版本；只有身份及完整歷史相同的已選預算先導紀錄才重用。執行前重新比對執行檔雜湊、識別及 UCI 條件；條件不符時保留錯誤並要求另建先導／標記。
- `run_labeling` 單次八小時共用所有分組，持有實驗獨占鎖；每局面原子提交原始輸出、白方分數、最佳手、排除原因與穩定工作身份。停止及錯誤均退出，由使用者手動續跑；只跳過已提交局面。進度使用記憶體中的已提交資料，重開時才從逐筆紀錄重建，摘要落後不重複計入。
- `load_labeled_dataset` 僅接受所有局面已提交的快照，回傳有效局面；mate、最佳手吃子／升變、bound-only、殘局庫特殊分數／命中均保留原因後篩除，未知分數保存錯誤而不轉成 cp。有效盤數、局面數、階段分布與原資料排除及不足額均可在 UI 查看。
