# M09：固定共同開局線的成對比較、續跑與完整歷史回放

## 父規格

[規格：可操作、可續跑的 ML 小規模權重試驗與共同開局驗證](https://github.com/chad30877/chess-ai/issues/26)

## 要建置的內容

使用者可由固定開局資料建立 32 條共同開局線，預覽後以現有任意設定比較、交換黑白、停止續跑與回放；整條流程保留走棋歷史，不只傳入中局 FEN。

## 驗收條件

- [x] UI 先產生並凍結 32 條不同開局線，分散開局類型，依最多 12 手的實際合法前綴去重，顯示清單及每候選對單一基準 64 局；不足線數明確處理，不重複湊數。
- [x] 同一線對所有候選及交換黑白配對一致，重播後才開始搜尋；比較不在每一局臨時隨機抽不同開局。
- [x] 起始 FEN 與完整 UCI 前綴串接到搜尋、判和、序列化派工、保存、穩定工作識別、重開續跑與回放；非法或已終局線在開跑前處理。
- [x] 新版保存契約保留開局來源、前綴與歷史；既有 FEN 輸入作空前綴，舊比較與棋譜可讀，不能為缺少的歷史補造資訊。
- [x] 續跑從凍結清單及完整歷史重建未完成對局，完成局不重複計數；手數與回放包含開局前綴，保持進行中逐手顯示。
- [x] 高層比較／保存／續跑／回放測試覆蓋三次重複相關歷史、易位／吃過路兵、配對一致、截短與未完成統計，少量真實 spawn 驗證跨程序歷史與停止清理。
- [x] 由 Agent 透過 UI 事件整合測試或實際操作，用兩個既有設定跑短共同開局比較並重開續跑。
- [x] 更新簡短測試說明及目前開發計畫，保存驗證證據與限制。
- [x] 完成實作與文件的繁體中文 Git commit。

## 實作與驗證狀態（2026-10-24）

實作提交 `2f11af7`，相同數值設定檔的候選識別修正為 `66929ba`。UI 可由固定來源凍結 32 條開局線，按 ECO 類型分散、依實際合法前綴去重，每候選與基準交換黑白共 64 局。來源不足拒絕湊數，非法或依對局規則已終局的前綴在建立批次前拒絕。

驗證證據：

- `tests.self_play.test_common_openings` 經比較、保存及回放驗證三次重複歷史、易位、吃過路兵、固定前綴、截短未完成統計及不同歷史的工作識別；既有設定檔修改後仍從快照續跑，原棋譜不變、再次續跑不增加局數。兩個同數值但不同檔名的候選亦各有獨立工作與結果。
- 少量真實 spawn：同時兩組配對、每局兩個搜尋 worker，保留 6 手歷史後選出可申請三次重複的走法，兩候選各完成兩局和棋；另驗證搜尋中停止與程序清理。
- `test_common_openings_preview_stop_reopen_resume_and_replay` 透過 pygame UI 事件選兩份既有設定，產生／分頁預覽 32 線，以深度 1、總手數上限 12 執行短比較，保存後停止、關閉應用程式、重建 UI，從對局紀錄續跑並回放。這是 Agent 事件整合驗收，並未宣稱為使用者人工操作。預覽畫面另經實際渲染檢查。
- 實驗快照 v2、比較歷史契約 `history_version=1` 與棋譜 v3 保存來源、起始 FEN、完整前綴和後續走法；既有快照、FEN 比較與舊棋譜回歸保留。FEN 不補造歷史。
- 完整回歸於專用暫存目錄執行 `python -m unittest discover -s tests -t .`，349 項全部通過（173.167 秒）；先前全域暫存目錄的慢掃描已中止，不列為通過紀錄。
- 規範及需求雙軸審查各 0 項未修正問題；編譯檢查與 `git diff --check` 通過。專案未配置靜態型別檢查器。

限制：短比較及截短局只驗證操作、資料與恢復流程；沒有執行正式深度 3 長比較，也不據此宣稱棋力提升。手數包含開局前綴，若執行上限小於前綴，仍完整重播前綴後截短，不再搜尋。

人工重現：批次自動對戰 → 評分比較 → 選基準及候選 → 產生 32 條共同開局線 → 下一頁查看 → 返回設定，設深度 1、手數上限 12 → 開始，待保存後停止 → 關閉重開 → 對局紀錄選該比較 → 續跑實驗 → 查看棋譜，確認前綴與手數一致。

## 執行與結案

一般 `/implement` 由 Agent 完成必要驗證並記錄證據，接著依專案 tracker 流程同步 GitHub 與本機票、索引及開發計畫，提交並關閉本票，最後讀回核對。供使用者重現的操作方式不是另一次必要人工驗收；不例行等待使用者操作或再次同意關票。真實失敗或缺少必要資源時先修復，無法完成才保留未勾選、開啟狀態並說明阻礙。

軟體驗收使用足以涵蓋行為的短流程；八小時停止以可控制時鐘驗證。正式完整資料與長時間對戰由使用者於交付後分次執行，不能把短流程結果宣稱為完整研究或棋力提升。
