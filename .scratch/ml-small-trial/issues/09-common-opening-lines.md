# M09：固定共同開局線的成對比較、續跑與完整歷史回放

## 父規格

[規格：可操作、可續跑的 ML 小規模權重試驗與共同開局驗證](https://github.com/chad30877/chess-ai/issues/26)

## 要建置的內容

使用者可由固定開局資料建立 32 條共同開局線，預覽後以現有任意設定比較、交換黑白、停止續跑與回放；整條流程保留走棋歷史，不只傳入中局 FEN。

## 驗收條件

- [ ] UI 先產生並凍結 32 條不同開局線，分散開局類型，依最多 12 手的實際合法前綴去重，顯示清單及每候選對單一基準 64 局；不足線數明確處理，不重複湊數。
- [ ] 同一線對所有候選及交換黑白配對一致，重播後才開始搜尋；比較不在每一局臨時隨機抽不同開局。
- [ ] 起始 FEN 與完整 UCI 前綴串接到搜尋、判和、序列化派工、保存、穩定工作識別、重開續跑與回放；非法或已終局線在開跑前處理。
- [ ] 新版保存契約保留開局來源、前綴與歷史；既有 FEN 輸入作空前綴，舊比較與棋譜可讀，不能為缺少的歷史補造資訊。
- [ ] 續跑從凍結清單及完整歷史重建未完成對局，完成局不重複計數；手數與回放包含開局前綴，保持進行中逐手顯示。
- [ ] 高層比較／保存／續跑／回放測試覆蓋三次重複相關歷史、易位／吃過路兵、配對一致、截短與未完成統計，少量真實 spawn 驗證跨程序歷史與停止清理。
- [ ] 由 Agent 透過 UI 事件整合測試或實際操作，用兩個既有設定跑短共同開局比較並重開續跑。
- [ ] 更新簡短測試說明及目前開發計畫，保存驗證證據與限制。
- [ ] 完成實作與文件的繁體中文 Git commit。

## 執行與結案

一般 `/implement` 由 Agent 完成必要驗證並記錄證據，接著依專案 tracker 流程同步 GitHub 與本機票、索引及開發計畫，提交並關閉本票，最後讀回核對。供使用者重現的操作方式不是另一次必要人工驗收；不例行等待使用者操作或再次同意關票。真實失敗或缺少必要資源時先修復，無法完成才保留未勾選、開啟狀態並說明阻礙。

軟體驗收使用足以涵蓋行為的短流程；八小時停止以可控制時鐘驗證。正式完整資料與長時間對戰由使用者於交付後分次執行，不能把短流程結果宣稱為完整研究或棋力提升。
