# M06：五個單群組共用預算學習與完整結果比較

## 父規格

[規格：可操作、可續跑的 ML 小規模權重試驗與共同開局驗證](https://github.com/chad30877/chess-ai/issues/26)

## 要建置的內容

讓使用者一次選擇五個單群組，沿用相同資料與教師尺度，分組完成訓練、續跑與誤差比較，選取需要的學習設定。

## 驗收條件

- [x] 棋子位置、兵形、活動力、王安全、協調均可獨立學習，合計涵蓋 32 個現有位置權重；未選群組保持關閉，零初始權重仍能變正。
- [x] 各組共用同一資料分組、教師標記與校準倍率，不因切換群組重估；原始單群組與學習設定具有相同階段規則。
- [x] 所有選定群組及三種強度共用整次八小時預算；完成候選逐個保存，停止、關閉及到時後只重跑未完成部分，不能每組重開八小時計時。
- [x] 結果按群組並列原始／學習的驗證與測試 MAE、相對純子力與 stable 的差異、各階段與有效樣本量，顯示已完成／失敗／未完成，不將排序宣稱最強。
- [x] 驗證與測試皆改善者可標示為優先對戰觀察，不設改善百分比硬門檻；未勝過 stable 不禁止保存或進入組合，無改善也可輸出完整結果。
- [x] 使用者可從結果選取候選、查看權重差異、另存與重新載入。各組測試結果遵守凍結後一次評估，改條件另建實驗並保留來源關係。
- [x] 高層流程測試涵蓋多群組共用預算、跨群組續跑、零權重學習、群組隔離及部分失敗；不用增加單純常數測試。
- [x] 由 Agent 透過 UI 事件整合測試或實際操作，跑兩組後停止並續跑其餘組，確認結果不重複。
- [x] 更新簡短測試說明及目前開發計畫，保存驗證證據與限制。
- [x] 完成實作與文件的繁體中文 Git commit。

## 執行與結案

一般 `/implement` 由 Agent 完成必要驗證並記錄證據，接著依專案 tracker 流程同步 GitHub 與本機票、索引及開發計畫，提交並關閉本票，最後讀回核對。供使用者重現的操作方式不是另一次必要人工驗收；不例行等待使用者操作或再次同意關票。真實失敗或缺少必要資源時先修復，無法完成才保留未勾選、開啟狀態並說明阻礙。

軟體驗收使用足以涵蓋行為的短流程；八小時停止以可控制時鐘驗證。正式完整資料與長時間對戰由使用者於交付後分次執行，不能把短流程結果宣稱為完整研究或棋力提升。
