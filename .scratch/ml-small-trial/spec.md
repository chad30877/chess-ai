# 規格：可操作、可續跑的 ML 小規模權重試驗與共同開局驗證

## 問題陳述

使用者想知道從教師評分學習現有評分項權重，是否值得繼續投入以提升棋力。目前只能手動調整設定，部分範例實際累加多個群組，難以理解單一評分項群組的作用，也無法從 UI 完成資料準備、教師標記及學習。王安全等群組可能必須搭配其他群組才有作用，不能只憑單組排名淘汰。

純子力的開局選擇可能對同分走法及搜尋條件敏感，但尚未實驗證實；反覆重跑同一確定性開局不能增加獨立證據。長時間實驗需要看得見進度、可停止與關閉後續跑，並有實際截圖教學說明各控制項何時使用。

## 解法

在現有應用程式提供從選資料、教師先導量測與標記、單群組或自選組合學習、查看獨立資料誤差、另存候選，到共同開局對戰驗證的完整流程。先比較純子力與五個單群組，保留現有 stable 作額外參考，再驗證活動力與王安全的搭配及使用者選定組合。

教師使用固定 Stockfish 19；學習固定棋子價值，只調現有非負位置權重。開局庫另供一般對戰／真人對 AI 選用；評分比較則使用事先凍結的共同開局線。首輪對戰固定深度 3／q4、同時 4 局、每局 1 個搜尋 worker、每張置換表 4,096 筆。交付可離線閱讀、附真實操作截圖的 HTML 教學。實驗可以得到「未改善或證據不足」的有效結論，不以必須提升棋力作為軟體交付條件。

## 實作決策

### 範圍與既有介面

- 沿用評分設定、評分器、比較執行、背景工作、逐局保存、不可變實驗快照、續跑及回放入口；新增一個學習實驗執行入口管理資料、教師、訓練與結果。UI 只提交工作與呈現狀態，不在畫面執行長工作或另造對戰引擎。
- 不先做橫跨專案的重構。必要的資料契約擴充隨第一個可完整操作的切片加入；既有手動權重比較與舊棋譜讀取繼續可用。新增格式有版本與明確相容規則，舊資料缺少歷史時不得捏造。
- 純子力為主要實驗對照；五個單群組為棋子位置、兵形、活動力、王安全與協調。新學習預設啟用相同階段混合規則，子力倍率固定 1，中殘局棋子價值均固定 P/N/B/R/Q＝1/3/3/5/9。保留 stable 的原始數值及關閉分階段的狀態，顯示為「子力＋棋子位置」，不宣稱已證明較強。全項設定留在既有效能及後續組合比較用途。
- 棋子位置使用現有整組 PST 倍率，並非每格或每種棋子各學一個值。五組共 16 個位置項，各有中局／殘局權重，合計 32 個；固定現有特徵、符號、階段模型與表格版本。

### 資料與教師

- 首輪來源為 Lichess 2013 年 1 月標準棋公開棋譜，保存來源、CC0 授權、下載版本／雜湊及抽樣種子。來源以串流處理，不要求把整個壓縮檔展開載入記憶體；支援 UI 選本機來源與可追溯取得方式。既有專案棋譜只作流程檢查，不冒充未見測試資料。
- 先排除重複棋譜，再固定抽取 500 盤，按整盤分為 350／75／75 盤訓練／驗證／測試，然後每盤最多抽 12 個局面。略過前 8 手，一方落子算一手。抽樣兼顧棋局階段、固定重現規則；不足額明確報告，不重複補足或放寬條件。
- 同組相同局面只留一份；跨組重複局面從所有組排除。去重依棋子位置、輪到方、易位權、有效吃過路兵資訊，不因回合計數不同視為新局面；去重鍵與搜尋保留和棋歷史的置換鍵用途不同。樣本仍保存來源棋譜及完整合法走法前綴。
- 排除已終局、受將、教師預見將死、教師最佳手為吃子／升變、只回傳上下界或殘局資料庫特殊分數的紀錄。保留原始標記及各排除原因、階段分布及最終有效量；篩選不保證留下的局面完全無戰術。教師不啟用殘局資料庫，遇無法解釋的輸出明確報錯，不把特殊分數當一般 cp。
- 教師固定 Stockfish 19，保存執行檔雜湊、引擎識別、選項、實際節點預算及處理版本。以 UCI 邊界傳遞起始局面與完整歷史，保存原始分數視角、轉換後白方分數及最佳手。先在訓練來源中取約 100 局面比較 50,000／200,000 節點，報告耗時、分數差異與篩除量；正式預算由使用者看量測後選定並凍結，不預先宣稱任一預算品質足夠。
- 同一標記快照固定引擎選項及逐局面狀態初始化政策，避免續跑結果暗中依賴前次教師快取。下載／引擎不存在、版本不合、異常終止、逾時、非法最佳手及保存失敗都須在 UI 顯示原因；已成功成果保留。

### 校準、訓練及評估

- 只在訓練組，以固定 stable 的局面靜態評分為參照，對白方教師分數估計一次、不含截距、逐盤等權的最小平方倍率。其後所有群組與驗證／測試共用同倍率，不能每組重估。Stockfish 仍是教師；stable 只提供本專案的分數尺度，100 cp 不直接等同本專案一兵。
- 保存參照快照、校準殘差及訓練子集倍率穩定性診斷。零分母、非有限或非正倍率不可默默改為 1；UI 呈現無法校準，保留資料以供處理。穩定性診斷方式與標示規則在執行前固定於快照，異常時不得自動產生可靠排名或晉級宣告，也不得查看測試後修改規則。
- 訓練為非負線性最小平方，目標為逐盤等權的教師擬合誤差，加上按各權重尺度標準化的偏離原始權重平方懲罰。固定子力，只有選定群組可變；分階段後的特徵向量須精確對應正式評分器，不另定一套分數算法。
- 先試弱／中／強三個固定懲罰強度，由驗證組選擇；具體值、正尺度、數值求解器版本／容差及同分選擇順序在實驗開始前寫入快照。這些是可重現的實作參數，不得依測試結果調整。不加統一百分比硬上限，已啟用零權重可學成正值；其尺度採固定正絕對值，未選群組保持關閉。
- 驗證挑選完成後凍結候選，再對測試組評估一次。重新開啟顯示保存結果，不重新擬合或重新挑選；修改條件建立新實驗並標示資料沿用，不能把已看過的測試重新宣稱未見資料。
- 主要指標為逐盤平均 MAE：先平均每盤保留局面的絕對誤差，再平均各盤，無有效局面的棋譜不當成零誤差。另報階段分層、各組盤數與局面數。並列純子力、同群組原始與學習設定、stable，分清群組增益與學習增益。
- 驗證及測試皆改善者優先進入對戰觀察，不設 5%／10% 硬門檻，也不把未勝過 stable 視為失去組合價值。沒有改善、資料不足或求解未完成都是真實結果，不輸出虛假成功或棋力結論。
- 第一個訓練切片以棋子位置走通完整流程，再擴充五個單群組；UI 可勾選組合，不自動展開所有群組排列。直接組合沿用各單組學習數值，聯合訓練同時調整所選群組；兩者身份與結果分開保存。
- 預先安排活動力＋王安全，不以王安全單組勝出為前提。在同資料、固定權重與一致階段規則下比較純子力、加活動力、加王安全、兩者皆加的四設定，呈現兩種背景下加入王安全的增量；聯合重訓另列。現有加法評分器沒有新增交互特徵，觀察的是誤差及對戰的搭配效果。

### 執行、保存與 UI

- 教師標記與訓練各自每次執行最多 8 小時；同次選定的所有群組及候選共用訓練預算，不逐組重置。時間到保存已完成工作並停止，不自動重啟；停止或關閉後由使用者手動續跑。
- 教師以完成局面、訓練以完成候選為提交單位。未完成候選可重跑，不承諾數值求解器中途續算。預算到期或停止時不能無限等待求解器；隔離長工作並處理停止、程序清理及原子提交，未完成輸出不算成功。
- 快照涵蓋資料分組、來源／版本、教師、篩選、特徵、校準、群組、原始值、訓練條件及結果身份。沿用可恢復保存與獨占執行思路，避免雙重派工及重複計數；條件改變另建實驗，不覆寫原始設定或已完成候選。
- UI 提供目前階段、已完成、剩餘、需重跑、耗時與失敗原因，進階條件收起。結果可查看權重前後差異、排序及另存完整合法設定，並直接選入既有對戰比較。保持頁面簡短，不堆疊由元件狀態已可理解的說明。

### 開局與對戰

- 使用 Lichess 具名開局資料（CC0），保存來源版本與完整合法序列。一般對戰／真人對 AI 可選擇啟用：在目前局面收錄的不同合法走法間等機率選擇，不依開局名稱出現次數加權；不暗示資料包含勝率權重或逐線棋力保證。
- 預設最多使用開局庫 12 手，UI 可調；首次查無走法或達上限，該局永久離庫並使用 Alpha-Beta。保存種子、已走序列與離庫狀態，重新開始新局才重置；真人選步也須更新當局是否已離庫。
- 比較先固定 32 條不同開局線，分散選取不同開局、依實際序列排除重複，於執行前保存清單。按共同 12 手上限截取合法前綴，可較短；所有設定重播相同線後才搜尋。每條交換黑白，每個候選對一個基準共 64 局；若另選 stable 參考比較，獨立顯示額外局數，不能把兩個基準混成同一個 64 局分母。
- 開局契約保存起始 FEN 加 UCI 走法前綴，串接棋盤、搜尋、派工、判和、工作識別、保存、續跑與回放；不能只傳開局結束 FEN。既有只有 FEN 的輸入等價於空前綴，原紀錄不補造歷史。非法序列在開跑前拒絕；開始搜尋前已終局的線明確處理並避免進入無意義比較。
- 本輪比較固定深度 3／q4、同時 4 局、每局 1 個搜尋 worker、TT 4,096 筆，雙方條件相同。沿用目前判和政策及手數限制控制，實際值必須納入快照，截短或中止不算和棋；不是把深度 3 的對戰結果拿去訓練，也不影響教師節點預算。
- 沿用逐場保存、完整配對統計、結果排序、回放、續跑，以及目前已完成的逐局手數／回合／輪到方顯示；開局前綴納入回放與手數定義，避免畫面從中局又從零誤數。報告逐開局結果與未完成量，不把換 seed 的確定性重跑算獨立證據，也不把 64 局初步觀察當棋力提升證明。

## 測試決策

- 以使用者能觀察的完整行為驗證，避免測試私有呼叫次數、固定文案、常數、import 或 SDK 呼叫存在。主測試入口為應用程式事件／學習實驗公開執行入口，經實際保存後重新開啟，連到現有比較與回放入口。
- 對資料分組、跨組去重、教師視角、篩選、共用尺度、固定子力、非負權重、驗證挑選與測試凍結，以小型可手算資料驗證外部結果。特徵向量與正式評分的一致性是重要數值契約，允許少量針對性行為測試，不測內部矩陣組裝細節。
- UCI 教師是唯一主要外部替身邊界，使用可控制的測試程序回傳分數、mate、bound、非法走法、超時及崩潰。資料分割、訓練、保存及續跑盡量用真實實作；真實 Stockfish 先導量測獨立執行，不放入日常測試或以固定引擎分數作脆弱斷言。
- 沿用現有權重實驗流程、續跑、比較執行、UI 事件及回放的測試方式，涵蓋停止、重新啟動、提交後摘要落後、儲存失敗與重複執行。用可控制時鐘驗證八小時總預算，不真的等待八小時。
- 開局以真人／批次／比較入口驗證合法走法、不同走法去重、離庫狀態、12 手界線、配對一致、完整歷史的重複判和、回放與舊格式相容。少量真實 spawn 測試驗證歷史與停止跨程序保留，其餘走高層流程即可。
- 首輪完整人工驗收由 UI 建立實驗、準備資料、真實教師先導／標記、學習、停止與重開續跑、另存及深度 3 對戰。完整資料與各候選 64 局可分次完成；未完成狀態需如實呈現，不以煙霧測試宣稱棋力。HTML 截圖以實際版本產生，人工核對流程與離線資源，不為靜態文案加測試。
- 測試入口及工作票切分經使用者確認後才發布；本草稿不表示已實作或已驗收。
