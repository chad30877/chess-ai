# T02：減少搜尋評分成本並驗證語意與耗時

## 所屬規格

規格 A：全評分設定下保持搜尋語意的效能改善。發布時換成父 issue 編號。

## 要交付的行為

搜尋只取得需要的數值評分，回放仍可取得完整分項說明；全部與部分評分項啟用時都保持原有評分語意，並以 T01 相同條件證明實際成本與延遲變化。

## 驗收條件

- [ ] 依 T01 剖析選定評分路徑中的具體成本；純數值入口避免建立僅供說明的完整分項，跳過沒有作用的停用項計算並避免不必要的重複特徵計算。
- [ ] 全項與混合設定、中局／殘局、零權重及特殊走法後的總分與既有分項介面一致；分項說明、設定版本與白方／兵單位語意保持。
- [ ] 公開搜尋入口的完成深度、分數、唯一最佳走法及原棋盤歷史正確；同分選步差異需證明等價並記錄。
- [ ] 真人及多程序搜尋使用同一評分語意，取消／故障／重開不殘留子程序或套用舊結果。
- [ ] 不刪和棋歷史、不更改將死尺度、不減少一般或延伸深度、不將 BOUND 當 EXACT。
- [ ] 以 T01 的全項與基準設定、代表局面交錯重跑前後比較，記錄完成深度與計數。全項路徑須有可重現的改善證據，未改善的案例與限制明列，不只呈現停用項獲益。
- [ ] 若評分優化無可重現收益，回報證據並修正方案，不以程式碼變短或微基準代替搜尋加速驗收；其他瓶頸只列後續建議，不擴張到選擇性搜尋。
- [ ] 通過既有相關搜尋、評分、取消與程序清理測試，補足重要回歸案例並更新人工測試方式。

## 被哪些工作阻擋

- T01：需要完整設定的實測基準與剖析。
