## 已確認方向

- 專案主線回到 ML：第一版以外部教師引擎評分學習現有評分項的權重，保留手工設定作對照，分別驗證獨立局面評分誤差與實際對戰表現。對局結果或混合目標留作後續比較，不必以神經網路為起點。
- 效能優先改善真人對戰單步等待，以全評分項啟用、一般搜尋深度 5 個半回合為目標情境；quiescence 深度另外記錄。目標是減少耗時，不設定秒數門檻，以相同條件的前後量測檢查改善。
- 首階段加速保持評分與搜尋語意，允許有效使用界限、置換表、走法排序及減少重複計算，不要求所有節點求得 EXACT。可能漏搜的選擇性搜尋技巧留待後續；同分走法因排序改變的情況另行記錄與檢查。
- 調參優先提供 UI，先完成「選評分權重與範圍 → 產生候選 → 比較 → 查看結果及另存」，再接 ML 訓練入口；沿用既有多候選比較、交換黑白、完整設定快照及結果保存。
- 比較 UI 支援多參數組合：例如兩個參數各選三個值，產生九組候選；執行前顯示候選數與預計對局數，也支援單參數比較。
- 參數輸入支援列舉數值及起點／終點／間隔，先預覽候選與基準差異。可用相對基準百分比調整並顯示實際權重，各項不要求合計 100%；保留實際權重輸入，基準為零時使用實際值。
- 結果以可排序比較表呈現參數差異、得分率、勝和敗、完成配對數、未完成數與耗時，提供棋譜檢視及另存設定；排序不等於宣告最強設定。
- 接受正式對戰與教師標記等實驗在本機執行數小時或過夜；短測用於檢查流程，不當作棋力證據。
- 實驗須能關閉程式後續跑，保留設定與已完成結果；尚未完成的棋局可重跑。後續教師標記與訓練也須可接續。
- 第一版比較固定評分項開關，只調已啟用項目的權重；輸入權重不會隱含啟用項目。要加入評分項，先建立明確啟用它的設定。
- 首輪 ML 固定棋子價值，學習 PST 倍率、兵形、活動力、王安全與協調項的權重，維持現有合法範圍。此為首輪實驗限制，後續仍可評估加入棋子價值學習。
- 訓練局面允許使用授權合適、來源可追溯的公開棋譜，搭配本專案對局，再由教師評分；涵蓋不同棋局階段，按整盤分開訓練與測試資料。
- 第一批效能已實作；比較 UI 已支援組合預覽、結果排序及保存快照續跑，ML 的細部規格留作下一批。

## 效能的接續工作

搜尋已使用純數值評分，避免建立回放用分項物件，略過無貢獻的停用群組；完整說明入口保留原始特徵與中局／殘局分項。固定全項與既有基準設定、代表局面、歷史、剖析及程序冷啟動／重用的重現命令與證據見[搜尋與評分](搜尋與評分.md)。

本輪僅優化評分路徑，沒有改一般或延伸深度、終局尺度、和棋歷史或界限使用方式。長中局仍可能逾時，後續應增加完成深度 5 的長樣本及輪數。python-chess 棋盤操作仍占顯著成本；歷史、快取與派工優化需各自取得證據後再立項，不能把刪除歷史或減深當成加速。

比較 UI 沿用固定基準與共同搜尋條件、同開局交換黑白的對局比較；實驗結果與未參與調整的局面驗證分開。後續學習產生的權重也可作為候選來源，第一版不含訓練入口。

評分權重與搜尋參數是不同實驗軸。現有評分比較要求雙方搜尋條件相同，不能直接拿來宣稱已支援搜尋參數調優。固定時間比較也尚未接入。不要以單一局面重複確定性對戰當成更多獨立樣本；訓練／驗證按整盤分組，另保留未參與調參的測試資料。既有 E1 已查看的局面集不能重新稱為未見測試集。

1. 先讀本文件及根目錄詞彙表，沿用已確認決策，不重問已回答的 Q1–Q15。
2. 依 `docs/agents/issue-tracker.md` 使用 `gh` 讀取規格 #18、#19 與工作票的最新內容及留言，不重建已發布 issues。GitHub CLI 已完成登入；目前本機使用的是暫存目錄中的官方可攜執行檔，若未在 PATH 可先定位該檔。
3. 第一批 A 與 B 已實作。先核對整合分支驗收與 GitHub 最新狀態；調參操作及人工測試見[評分調整與實驗](評分調整與實驗.md)。
4. 依工作票完成實作與驗收，每次改動提交 Git，提供人工測試方式並整理本文件。完整全評分剖析與評分優化證據已記錄，後續不得把未完成的中局量測當作深度 5 加速。
5. 接續 ML 時先選定具體資料集、教師版本與搜尋預算，做小規模標記／訓練試驗，再決定資料量、損失函數、中局／殘局權重處理與訓練接續方式。已確認的教師路線、固定棋子價值及公開／本機棋譜來源不必重談。

權重尺度維持既有定義：子力倍率固定 1，首輪固定棋子價值，因此位置權重全部乘 2 會改變相對子力的偏好。各評分項原始單位不同，不將係數占比稱為重要性或分數貢獻占比；固定 aspiration 視窗、將死分數及教師目標亦不隨 config 自動縮放，不將任意比例相同的設定直接視為整個引擎等價。

目前已有置換表，可在局面／歷史與搜尋條件相容時重用足夠深度的分數或界限；它不會消除首次遇到局面的評分成本。優化仍須依量測決定，不將既有置換表或排序列為尚未實作功能。

教師評分的目標是逼近指定引擎對局面的判斷，能為單一局面提供較細緻的學習訊號，但會受教師偏差、標記成本及現有特徵表達能力限制。對局結果學習直接使用完整棋局的勝和敗，不以外部引擎分數為目標，但結果也受後續失誤與對手強度影響，需要多樣資料及獨立驗證。從固定棋譜學結果仍屬監督式學習；自我對弈、依回饋更新策略並持續產生新資料則可另行設計為強化學習流程，不能將兩者混稱。現有特徵權重學習亦不等於自行學出新特徵。

成熟專案有不同路線：[Stockfish NNUE 文件](https://official-stockfish.github.io/docs/nnue-pytorch-wiki/docs/nnue.html) 說明以引擎評分訓練，以及混合對局結果的方式；[Lc0 訓練文件](https://lczero.org/dev/wiki/neural-net-training/) 說明使用自我對弈資料訓練。架構是否相同，不是能否使用教師資料的判準；若研究問題要求「完全不借助外部教師」，才需要獨立的無教師實驗。

教師誤差下降不代表棋力必然提升，也不以教師訓練結果證明從零自主學習。資料須記錄局面來源、教師版本及搜尋預算；訓練與測試分離，教師的特徵與網路不需照搬。

每階段收斂後才轉正式規格與 GitHub Issues，按依賴實作；完成時整理本文件，移除已失效的問題。

跨搜尋保留置換表仍延後：現有根距離鍵限制重用，保留未呈現有效命中。若量測後值得重啟，先處理將死分數正規化、和棋歷史及玩家／對局／評分設定失效邊界，研究證據見[搜尋與評分](搜尋與評分.md#跨搜尋保留評估)。
