## 任務粒度與交付規則

一次一個主要目標，包含必要的介面、設定、測試、文件與 Git commit。評分項目一次一組，搜尋一次一項或一組密切相關方法；不要把搬檔案、新特徵、搜尋優化與調參混成一個改動。

同一對話可依序完成多個明確階段，但每階段必須可獨立驗證與回滾。這是專案工作範圍建議，不是 GPT-6 Astra 的功能數量上限。跨區塊的必要呼叫與測試可一起調整；除本階段明確列出的移除項目外，保留其他區塊核心行為。

依 [AGENTS.md](../AGENTS.md)，每次改動須編寫或更新相關測試，交付前讓全部測試與驗證通過，再建立對應 commit。不可為了通過而刪掉仍有效的驗證；純分類需比對原有案例仍被發現並執行。階段完成後更新狀態、實際範圍與驗證結果；commit 由 Git 歷史追蹤。

CLI 保留 material（僅子力），新增 random；移除 ML 選項與相容別名。刪除 2 個 ML 專屬測試，混合檔案的非 ML 覆蓋保留，新增 6 個 CLI／對戰案例。完整 88 個測試與 `git diff --check` 通過，包括兩盤 Random／material 完整對戰及舊參數拒絕；UI、生成與回放由原有測試驗證。未搬動 engine/tests、調整評分／搜尋或刪除通用對局資料。

範圍：training 舊特徵／訓練程式、scripts 訓練入口、ML evaluator、engine_match 的 ML 選項、專屬引用／測試、已確認的模型／metrics 產物與已無用途的依賴說明。先列出確切刪除清單；本機產物路徑必須確認在預期目錄內。

不包含：刪對局資料、批次／棋譜、重做 UI、engine 或 tests 搬檔、調權重、改搜尋。

驗收：無舊 ML 執行引用；保留流程可用；ML 專屬 CLI 選項明確失效；CLI 的 Random 與保留選項經小型驗證；混合測試保留非 ML 覆蓋；完整測試通過，文件同步，獨立 commit。詳細邊界見 [評分調整與實驗](評分調整與實驗.md#舊-ml-移除驗收)。

```text
engine/
├── game.py
```

## P4 建立可調評分設定

狀態：待做。相依：P3。

將特徵計算、權重與分項輸出分開；固定白方視角與兵值 1 的尺度。保留現有子力參數能力，先新增 PST 倍率、統一設定／版本與實際設定保存；預設值重現 material + PST，PST 表內容不變。

各項定義原始值、單位、方向、權重及加權貢獻；對戰紀錄必須來自實際使用設定，不從新建的預設玩家猜測。格式見 [搜尋與評分](搜尋與評分.md#獨立權重與設定規劃)。

不包含：新兵形／活動力等特徵、重新調子力、訓練模型或自動調參。

驗收：預設結果等價、參數驗證、權重／開關效果、分項加總、設定往返及實際對戰紀錄一致；必要的 schema 擴充保持舊資料可讀。獨立 commit。

## P5 建立設定比較流程

狀態：待做。相依：P4。

支援新／穩定設定從相同初始局面交換黑白比較，Random 保留基本基準。分清固定深度與固定時間預算，保存雙方真實設定、種子、版本及結果；新功能驗證先使用小批次，不在預設測試跑長時間調參。

驗收：比較設定可重現、顏色安排正確、截斷不算和棋、統計與設定可追溯。小樣本只驗證流程，不等同棋力證明。見 [評分調整與實驗](評分調整與實驗.md#手動比較流程規劃)。

## P6 分批擴充評分與搜尋

狀態：待做。相依：P4；要宣稱棋力效果需 P5。

評分工作按 E1–E5 分批；搜尋按 S0–S5 分批，詳見 [評分擴充規劃](搜尋與評分.md#評分擴充規劃) 與 [搜尋擴充規劃](搜尋與評分.md#搜尋擴充規劃)。每次選一個子項，不把本節當成一次全部完成的授權。

新特徵必須一起定義權重、預設開關、分項輸出與測試；實作符合規格和是否提升棋力分別記錄。開局庫屬選步來源，另行安排，不當成靜態評分項。

## P7 評估自動調參

狀態：遠期待評估。相依：P5 與至少一輪穩定的 P6 實驗。

先驗證手動調整有效，再選小範圍參數搜尋或其他方法；不恢復舊 ML 路線。先定目標、資料分組與獨立驗證集，避免只追求對 Random 的高勝率。這一階段需另定具體規格，不預先實作空框架。
