更新日期：2026-10-16。本文件保留目前狀態與後續方向；實作歷史由 Git 保存。

## 目前狀態

| 範圍 | 目前狀態 |
| --- | --- |
| 局面評分 | 回放可查看靜態總分、評分項分解及評分設定草稿，另存版本化 JSON |
| 真人對 AI | Random、Greedy、固定深度 Alpha-Beta；可設定搜尋 worker 與置換表容量 |
| 一般批次 | 支援 Alpha-Beta 雙方對戰；同時對局數與搜尋 worker 獨立設定，逐場保存，保留暫停／停止 |
| 評分比較 | UI／CLI 的基準與多候選使用共同搜尋條件、交換黑白、逐場保存；結果不自動排名 |
| 搜尋與資源 | 跨核心程序根分枝、有界私有置換表、保留和棋歷史的整數置換鍵、取消／故障清理與實際條件快照 |
| 效能驗證 | 固定深度 5 與兩層 worker 的有限基準見[搜尋與評分](搜尋與評分.md)，不限制兩層 worker 乘積 |

## 後續方向

- 依固定搜尋條件、相同開局與交換黑白的對局比較驗證評分設定，再以未參與調整的局面驗證。評分項集合維持現況；新評分項、自動調參與固定時間比較另立規格。
- 跨搜尋保留置換表先延後：現有根距離鍵限制重用，保留未呈現有效命中。若另行實作，先規格化將死分數正規化、歷史與和棋政策、評分設定及單一玩家／對局失效邊界；研究證據見[搜尋與評分](搜尋與評分.md#跨搜尋保留評估)。
- 持續觀察不同局面的程序啟動、搜尋分枝放大量與記憶體成本；不要以 CPU 使用率代替延遲改善，也不把短局基準當作棋力證明。

詳細比較方法見[評分調整與實驗](評分調整與實驗.md)。名稱／標籤搜尋、悔棋、索引快取及中斷修復依需求另行安排。
