## 任務粒度與交付規則

一次一個主要目標，包含必要的介面、設定、測試、文件與 Git commit。評分項目一次一組，搜尋一次一項或一組密切相關方法；不要把搬檔案、新特徵、搜尋優化與調參混成一個改動。

同一對話可依序完成多個明確階段，但每階段必須可獨立驗證與回滾。這是專案工作範圍建議，不是 GPT-6 Astra 的功能數量上限。跨區塊的必要呼叫與測試可一起調整；除本階段明確列出的移除項目外，保留其他區塊核心行為。

依 [AGENTS.md](../AGENTS.md)，每次改動須編寫或更新相關測試，交付前讓全部測試與驗證通過，再建立對應 commit。不可為了通過而刪掉仍有效的驗證；純分類需比對原有案例仍被發現並執行。階段完成後更新狀態、實際範圍與驗證結果；commit 由 Git 歷史追蹤。

## P5 建立設定比較流程

狀態：已完成（2026-09-09）。相依：P4。

實際範圍：新增 `ComparisonParticipant` 與 `run_evaluation_comparison()`，每個初始 FEN／重複次數固定一個 pair seed，依序執行 baseline 白／candidate 黑及 candidate 白／baseline 黑。支援兩份 `EvaluationConfig` 或 Random baseline；雙方標籤與實際完整設定保存在 manifest 及 `comparison.json`，每盤仍保存 games、positions 與 replay。

比較預算明確記為 `fixed_depth, depth_plies=1`，對應目前 Greedy 的一手選步。因搜尋 `time_ms` 尚未生效，本階段不接受固定時間參數；待 S3 真正實作時間控制後才能新增 time-budget 比較，避免混合或誤標。摘要依 candidate／baseline 視角分別保存勝和敗、未完成、完成場數與分數；截斷不算和棋，另保存配對色彩、初始 FEN、種子、結果、終止原因及耗時。

提供 `scripts.compare_evaluations` CLI 與兩份可直接使用的版本化設定範例。新增 7 個流程／CLI／範例驗證後完整 105 個測試與 `git diff --check` 通過；測試只用終局或短截斷局面，不宣稱棋力效果。

支援新／穩定設定從相同初始局面交換黑白比較，Random 保留基本基準。分清固定深度與固定時間預算，保存雙方真實設定、種子、版本及結果；新功能驗證先使用小批次，不在預設測試跑長時間調參。

驗收：比較設定可重現、顏色安排正確、截斷不算和棋、統計與設定可追溯。小樣本只驗證流程，不等同棋力證明。已完成並建立獨立 commit；見 [評分調整與實驗](評分調整與實驗.md#手動比較流程)。

狀態：進行中；S0–S2 已完成，其餘子項待做。相依：P4；要宣稱棋力效果需 P5。

S0 實際範圍：新增 Alpha-Beta／Greedy 共用的終局分數映射，透過 `engine.game.get_outcome()` 使用一致的 `claim_draw` 政策；搜尋和 Greedy 的子分支保留完整 move stack。生成器、UI 對局、UI 批次及 P5 設定比較會把對局政策傳入 Greedy，`AlphaBetaSearcher`／`AlphaBetaPlayer.from_evaluator()` 也可直接指定。正常選步及 evaluator 例外後，呼叫者的根棋盤 FEN 與 move stack 均不變。

S0 新增 9 個終局、申請和棋、五次重複、政策傳遞及棋盤隔離案例；調整 1 個原本誤用已自動和棋局面的既有選步測試資料。完整 114 個測試與 `git diff --check` 通過。未新增評分特徵、move ordering、quiescence、時間控制或 Alpha-Beta UI／CLI 選項。

S1 實際範圍：Alpha-Beta 預設先搜尋升變，再依升變棋子價值排序；其後搜尋吃子並用簡單 victim／attacker 子力值排序，quiet moves 維持原相對順序。`move_ordering=False` 保留未排序基準，`AlphaBetaPlayer.from_evaluator()` 可傳入同一開關。固定 depth 3 驗收局面的最佳走法與 -5 分數一致，節點由 1,529 降至 411；本機單次時間約由 0.048 秒降至 0.013 秒，但不宣稱每個局面都會加速。

S1 新增 5 個排序規則、開關、玩家傳遞與搜尋等價／節點案例後，完整 119 個測試與 `git diff --check` 通過。未加入 PV、TT、history heuristic、quiescence、時間控制或評分變更。

S2 實際範圍：一般深度邊界預設以最多 4 ply quiescence 延伸吃子與升變，非受將局面可用靜態分數 stand-pat；受將局面搜尋全部合法應將。`quiescence_depth=0` 完全停用以保留舊基準；已進入 quiescence 後若硬上限仍受將，固定再搜尋一層應將後停止。`depth_reached` 包含延伸深度，節點與剪枝統計也納入 quiescence。

S2 新增 6 個設定驗證、玩家傳遞、交換地平線、受將應對與停止邊界案例後，完整 125 個測試與 `git diff --check` 通過。depth 1 功能局面由誤吃後被回吃改為避開交換；這不等同棋力實驗。未加入一般 checking move 延伸、delta pruning、迭代加深、時間／取消或評分變更。

評分工作按 E1–E5 分批；搜尋按 S0–S5 分批，詳見 [評分擴充規劃](搜尋與評分.md#評分擴充規劃) 與 [搜尋擴充規劃](搜尋與評分.md#搜尋擴充規劃)。每次選一個子項，不把本節當成一次全部完成的授權。

新特徵必須一起定義權重、預設開關、分項輸出與測試；實作符合規格和是否提升棋力分別記錄。開局庫屬選步來源，另行安排，不當成靜態評分項。
