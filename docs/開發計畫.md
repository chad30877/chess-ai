## 已確認方向

- 專案主線回到 ML：第一版以外部教師引擎評分學習現有評分項的權重，保留手工設定作對照，分別驗證獨立局面評分誤差與實際對戰表現。對局結果或混合目標留作後續比較，不必以神經網路為起點。
- ML 小規模試驗以判斷評分權重學習是否值得繼續投入來提升棋力為目的，不以成功訓練出模型作為達標條件；有證據支持不繼續投入，也可作為試驗結論。第一輪使用現有設備、不增加算力支出；教師標記與訓練每次執行最多 8 小時，五組訓練共用整次預算，不能每組重新計時。到時保存進度並停止，不自動連續重啟；保留已完成組別，由使用者查看結果後手動續跑剩餘工作。以完整試驗流程、必要 UI、停止續跑與附截圖的 HTML 教學控制交付範圍，不設兩天開發上限；多實驗管理及額外美化留待後續。具體驗收判準仍待收斂。
- 小試驗用來判斷是否值得進入正式對戰驗證；獨立局面誤差改善只支持繼續驗證，不等於棋力提升，無改善亦不直接否定所有 ML 路線。首輪採純子力為主要實驗對照，以及子力分別搭配棋子位置、兵形、活動力、王安全、協調的五個單群組試驗；先理解各組效果，再決定更多群組組合。各單群組設定維持相同階段規則與搜尋條件；學習期間固定該組開關及棋子價值。
- 保留現有 `stable.json` 作額外完整設定參考，UI 顯示「子力＋棋子位置」；其分階段開關關閉，不將它誤認為純子力或已證明較強的設定。另建清楚命名的純子力設定，不覆寫 stable，以保留既有預設與重現條件。全項設定保留既有效能量測用途，留待組合階段再比較，不作首輪共同基準。
- 各組結果並列純子力、子力加該群組的原始權重、子力加該群組的學習後權重，分開觀察加入群組與 ML 調整權重的效果。
- 單群組試驗後，預先安排「活動力＋王安全」搭配驗證，不以王安全單組勝出為前提。以純子力、子力＋活動力、子力＋王安全、子力＋活動力＋王安全四份設定，在相同資料與評估條件下先固定權重只切換開關，比較兩種背景下加入王安全的增量效果；重新聯合訓練另列結果。其他組合依具體假設安排，教師誤差與實際對戰分開驗證。
- 本輪 ML 小試驗須能由 UI 完成選資料、教師設定與標記、訓練、查看結果、另存候選設定及進入既有對戰比較；提供進度、失敗原因、停止與續跑，進階設定收起。附可離線開啟的 HTML 教學，包含入門流程、依調整目的查找的說明及帶編號重點標示的實際畫面截圖；說明對應控制項、調整方向、代價及結果查看位置，區分手動改權重與評分權重學習。
- 第一版 UI 支援「勾選評分項群組 → 建立組合 → 聯合訓練 → 比較／另存」，預設提供五個單群組及活動力＋王安全，也可自行選擇其他組合；由使用者明確選擇要跑的組合，不自動展開全部組合。多群組可先以各單組學習權重建立直接組合，再一起調整所選群組的權重；直接組合與聯合訓練的設定及結果分開保存，教學以活動力＋王安全示範。
- 設定選擇須呈現易懂的中文名稱、實際啟用內容與分階段開關，教學說明各評分項群組的用途與可調權重。現有累加範例的檔名只表示最後加入的群組，不能據此把它當作單群組設定。
- 本輪開局庫使用 [Lichess 具名開局資料](https://github.com/lichess-org/chess-openings)（CC0），提供開局名稱與完整走法，沒有勝率權重或逐線棋力保證。一般對戰／真人對 AI 可選擇啟用，從目前局面收錄的不同走法中等機率選擇；預設最多走 12 手（雙方各 6 步），UI 可調整，首次查不到或達上限後該局持續使用 Alpha-Beta，不再重新進入開局庫。
- config 比較第一輪預先固定 32 條不同開局線，分散選取不同開局並排除重複；各設定重播相同序列後才開始搜尋，每條交換黑白，每組候選對基準共 64 局。執行前保存清單，報告各開局結果，只作初輪觀察，不單憑總勝率宣告棋力提升。保存起始局面與完整合法走法前綴，搜尋、判和、派發、續跑及回放皆保留開局歷史。
- 開局庫比較測量指定開局後的表現，不據此宣稱評分器自行學會開局；單純換 seed 重跑確定性對局不增加獨立證據。
- 首輪以 [Lichess 2013 年 1 月公開棋譜](https://database.lichess.org/)為主要資料來源，固定來源後抽樣；本專案既有棋譜先用於流程檢查，資料年代與玩家分布限制記入結果。教師固定採 Stockfish 19 及其設定，先用約 100 個局面比較每局面 5 萬／20 萬節點的耗時與評分差異，再決定正式標記預算；兩個節點數是待量測選項，不代表品質保證。
- 教師分數先由訓練組校準共用倍率，再固定用於基準與候選；驗證／測試組不得重新估計。報告保留原始教師分數與校準方式，不將 Stockfish 的 100 cp 直接認定等於本專案多一兵；校準估計方法仍待細化。
- 首輪抽取 500 盤，每盤最多 12 個局面，總量上限約 6,000 個；固定抽樣種子，先按整盤以 70%／15%／15% 分為訓練／驗證／測試組（350／75／75 盤），再抽局面，兼顧不同棋局階段。訓練組學習權重，驗證組挑選設定，設定確定後才評估測試組。
- 先排除重複棋譜，略過開局前 8 手（一方落子算一手）；同組相同局面只留一份，跨組重複局面從各組排除。以棋子位置、輪到方、易位權及有效吃過路兵資訊比對，不以回合計數不同當作新局面。接受篩選後不足 6,000 個局面，報告實際保留量與各階段分布，不為湊數放寬規則。
- 首輪排除已終局、受將、教師預見將死、教師最佳手為吃子／升變，以及教師只回傳分數上下界或殘局資料庫特殊分數的紀錄。保留原始標記及各項排除原因與數量；這會限制試驗適用範圍，亦不保證留下的局面完全沒有戰術因素。
- 效能優先改善真人對戰單步等待，以全評分項啟用、一般搜尋深度 5 個半回合為目標情境；quiescence 深度另外記錄。目標是減少耗時，不設定秒數門檻，以相同條件的前後量測檢查改善。
- 首階段加速保持評分與搜尋語意，允許有效使用界限、置換表、走法排序及減少重複計算，不要求所有節點求得 EXACT。可能漏搜的選擇性搜尋技巧留待後續；同分走法因排序改變的情況另行記錄與檢查。
- 調參優先提供 UI，先完成「選評分權重與範圍 → 產生候選 → 比較 → 查看結果及另存」，再接 ML 訓練入口；沿用既有多候選比較、交換黑白、完整設定快照及結果保存。
- 比較 UI 支援多參數組合：例如兩個參數各選三個值，產生九組候選；執行前顯示候選數與預計對局數，也支援單參數比較。
- 參數輸入支援列舉數值及起點／終點／間隔，先預覽候選與基準差異。可用相對基準百分比調整並顯示實際權重，各項不要求合計 100%；保留實際權重輸入，基準為零時使用實際值。
- 結果以可排序比較表呈現參數差異、得分率、勝和敗、完成配對數、未完成數與耗時，提供棋譜檢視及另存設定；排序不等於宣告最強設定。
- 接受正式對戰與教師標記等實驗在本機執行數小時或過夜；短測用於檢查流程，不當作棋力證據。
- 實驗須能關閉程式後續跑，保留設定與已完成結果；尚未完成的棋局可重跑。教師標記逐局面保存，訓練逐個已完成候選設定保存；續跑跳過已完成工作，只重跑未完成的標記或訓練候選。UI 顯示已完成、剩餘及需重跑部分；修改資料、群組或訓練條件時建立新實驗，避免混用舊結果。
- 第一版比較固定評分項開關，只調已啟用項目的權重；輸入權重不會隱含啟用項目。要加入評分項，先建立明確啟用它的設定。
- 首輪 ML 固定棋子價值，各單群組分別學習其中局與殘局權重，維持非負合法範圍；五組共涵蓋 32 個位置權重，不直接進行全項聯合學習，再接已確認的活動力＋王安全搭配驗證。各組共用局面資料、教師標記及教師尺度校準倍率。已啟用群組內的零權重可學成正值，另設絕對尺度限制變動；未選群組保持關閉。後續仍可評估其他群組組合與棋子價值學習。
- 訓練採非負線性最小平方法，降低教師誤差並加入偏離原始權重的軟性懲罰；先試弱、中、強三種固定強度，由驗證組挑選。改善足夠時允許權重改變較多，不另設統一百分比硬上限；UI 顯示學習前後數值。各項尺度與三個強度值須事先固定，不能依測試組結果調整。
- 訓練局面允許使用授權合適、來源可追溯的公開棋譜，搭配本專案對局，再由教師評分；涵蓋不同棋局階段，按整盤分開訓練與測試資料。
- 第一批效能已實作；比較 UI 已支援組合預覽、結果排序及保存快照續跑，ML 的細部規格留作下一批。

## 效能量測收尾與後續邊界

搜尋已使用純數值評分，避免建立回放用分項物件，略過無貢獻的停用群組；完整說明入口保留原始特徵與中局／殘局分項。固定全項與既有基準設定、代表局面、歷史、剖析及程序冷啟動／重用的重現命令與證據見[搜尋與評分](搜尋與評分.md)。

中局補測固定深度 5／q4、單 worker、單次上限 120 秒，兩設定的優化前後各三輪皆完成。全項中位耗時 71.608→57.559 秒，基準 82.674→40.137 秒；各設定前後完整搜尋結果一致。這只支持固定中局的改善，不代表所有長中局或多程序皆有相同收益。

已確認本輪以有限預算補齊證據後轉 ML；若逾時就回報最後完整深度與限制，不延長預算，也不將未完成結果算作深度 5 證據。此次沒有逾時，不再把進一步加速或擴大局面樣本當作 ML 前置門檻。python-chess 棋盤操作、歷史、快取與派工優化留待有需求及證據時另行立項。

權重尺度維持既有定義：子力倍率固定 1，首輪固定棋子價值，因此位置權重全部乘 2 會改變相對子力的偏好。各評分項原始單位不同，不將係數占比稱為重要性或分數貢獻占比；固定 aspiration 視窗、將死分數及教師目標亦不隨 config 自動縮放，不將任意比例相同的設定直接視為整個引擎等價。

目前已有置換表，可在局面／歷史與搜尋條件相容時重用足夠深度的分數或界限；它不會消除首次遇到局面的評分成本。優化仍須依量測決定，不將既有置換表或排序列為尚未實作功能。

教師評分的目標是逼近指定引擎對局面的判斷，能為單一局面提供較細緻的學習訊號，但會受教師偏差、標記成本及現有特徵表達能力限制。對局結果學習直接使用完整棋局的勝和敗，不以外部引擎分數為目標，但結果也受後續失誤與對手強度影響，需要多樣資料及獨立驗證。從固定棋譜學結果仍屬監督式學習；自我對弈、依回饋更新策略並持續產生新資料則可另行設計為強化學習流程，不能將兩者混稱。現有特徵權重學習亦不等於自行學出新特徵。

成熟專案有不同路線：[Stockfish NNUE 文件](https://official-stockfish.github.io/docs/nnue-pytorch-wiki/docs/nnue.html) 說明以引擎評分訓練，以及混合對局結果的方式；[Lc0 訓練文件](https://lczero.org/dev/wiki/neural-net-training/) 說明使用自我對弈資料訓練。架構是否相同，不是能否使用教師資料的判準；若研究問題要求「完全不借助外部教師」，才需要獨立的無教師實驗。

教師誤差下降不代表棋力必然提升，也不以教師訓練結果證明從零自主學習。資料須記錄局面來源、教師版本及搜尋預算；訓練與測試分離，教師的特徵與網路不需照搬。
