## 已確認方向

- 專案主線回到 ML：第一版以外部教師引擎評分學習現有評分項的權重，保留手工設定作對照，分別驗證獨立局面評分誤差與實際對戰表現。對局結果或混合目標留作後續比較，不必以神經網路為起點。
- 效能優先改善真人對戰單步等待，以全評分項啟用、一般搜尋深度 5 個半回合為目標情境；quiescence 深度另外記錄。目標是減少耗時，不設定秒數門檻，以相同條件的前後量測檢查改善。
- 調參優先提供 UI，先完成「選評分權重與範圍 → 產生候選 → 比較 → 查看結果及另存」，再接 ML 訓練入口；沿用既有多候選比較、交換黑白、完整設定快照及結果保存。
- 比較 UI 支援多參數組合：例如兩個參數各選三個值，產生九組候選；執行前顯示候選數與預計對局數，也支援單參數比較。
- 首輪 ML 固定棋子價值，學習 PST 倍率、兵形、活動力、王安全與協調項的權重，維持現有合法範圍。此為首輪實驗限制，後續仍可評估加入棋子價值學習。
- 本輪仍在 grill，尚未完成正式規格、GitHub Issues 或實作範圍確認。以下階段是待收斂的規劃，不代表已交付功能。

## 效能診斷的起點

已確認 `HandcraftedEvaluator.evaluate()` 會呼叫完整分項評分；未啟用的評分項仍計算原始特徵。即使全部啟用，搜尋仍建立分項說明物件與字典，開啟階段混合時還有中局、殘局及混合分項。這是可量測的工作量，尚未證明其耗時占比。

其他待量測的路徑包括搜尋節點數與延伸、子局面棋盤與歷史複製、置換鍵回溯歷史，以及多程序派工。不能直接移除和棋歷史，也不能預設增加 worker 或關閉延伸一定更快；既有基準顯示效果依局面而異。

2026-10-23 初步基準使用預設評分、單 worker、q4、目標深度 5、每局 2 秒上限：標準開局約 2.002 秒完成深度 4，中局約 1.997 秒完成深度 3，均逾時。這只確認現有量測入口可執行；不是全評分設定的重現，也不是已約定的驗收門檻。

重現命令（輸出為本機暫存，不納入版本控制）：

```powershell
& ./.venv/Scripts/python.exe tools/benchmark_search.py --depth 5 --cases start middlegame --workers 1 --repeats 1 --steps 0 --timeout-ms 2000 --quiescence-depth 4 --no-memory-sampling --output "$env:TEMP/chess-grill-perf-facts.json"
```

現有 benchmark 固定使用預設評分器，未提供評分設定檔入口。下一階段須固定全評分設定、代表局面及硬體條件，建立可重跑基準並量測各路徑，才決定優化順序。優化後同時確認分數／走法語意及單步延遲；耗時不作不穩定的 CI 斷言。

| 階段 | 預期成果 | 尚待決定 |

| 搜尋效能 | 全評分設定的重現與剖析、依證據減少耗時，不設秒數門檻 | 局面集、是否容許選步改變 |
| 調參 UI | 第一版支援單參數及多參數組合候選、比較與檢視結果，訓練入口後接 | 可調參數清單、數值輸入方式、候選數量管理、實驗預算及結果呈現 |
| 評分權重學習 | 固定棋子價值，以教師評分學習位置相關權重，獨立驗證及實際對戰驗證 | 教師版本與搜尋條件、資料來源及預算、損失函數、中局／殘局權重處理 |

比較 UI 的方向已確認：固定基準與實驗條件，指定評分權重及範圍產生候選，執行比較、檢視結果並另存。細部建議為一次調整少量參數，同開局交換黑白比較，查看勝和敗、未完成數及耗時，再以未參與調整的資料驗證；這些實驗細節尚待收斂。後續學習產生的權重也可作為候選來源，第一版不含訓練入口。

評分權重與搜尋參數是不同實驗軸。現有評分比較要求雙方搜尋條件相同，不能直接拿來宣稱已支援搜尋參數調優。固定時間比較也尚未接入。不要以單一局面重複確定性對戰當成更多獨立樣本；訓練／驗證按整盤分組，另保留未參與調參的測試資料。既有 E1 已查看的局面集不能重新稱為未見測試集。

## 下次接續位置

教師評分、UI 多參數組合及首輪固定棋子價值已確認。先釐清加速的結果保留要求，再細化 UI、資料、教師條件、資源預算及驗收方式。

目前已有置換表，可在局面／歷史與搜尋條件相容時重用足夠深度的分數或界限；它不會消除首次遇到局面的評分成本。Q7 要區分保持搜尋語意的優化與可能改變結果的選擇性搜尋，並非提議重新新增置換表。若調整搜尋順序，還須區分同分走法的選擇改變與搜尋分數改變；具體驗收契約尚待確認。

教師評分的目標是逼近指定引擎對局面的判斷，能為單一局面提供較細緻的學習訊號，但會受教師偏差、標記成本及現有特徵表達能力限制。對局結果學習直接使用完整棋局的勝和敗，不以外部引擎分數為目標，但結果也受後續失誤與對手強度影響，需要多樣資料及獨立驗證。從固定棋譜學結果仍屬監督式學習；自我對弈、依回饋更新策略並持續產生新資料則可另行設計為強化學習流程，不能將兩者混稱。現有特徵權重學習亦不等於自行學出新特徵。

成熟專案有不同路線：[Stockfish NNUE 文件](https://official-stockfish.github.io/docs/nnue-pytorch-wiki/docs/nnue.html) 說明以引擎評分訓練，以及混合對局結果的方式；[Lc0 訓練文件](https://lczero.org/dev/wiki/neural-net-training/) 說明使用自我對弈資料訓練。架構是否相同，不是能否使用教師資料的判準；若研究問題要求「完全不借助外部教師」，才需要獨立的無教師實驗。

教師誤差下降不代表棋力必然提升，也不以教師訓練結果證明從零自主學習。資料須記錄局面來源、教師版本及搜尋預算；訓練與測試分離，教師的特徵與網路不需照搬。
