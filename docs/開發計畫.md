## 已確定的決策

- 保留既有 UI 自動對戰、真人操作、日期回放、批次資料及共用棋規；保留 `assets/pieces` 與 SVG 失敗時的 PNG 備援。
- 舊 ML 已移除，不恢復舊模型或相容別名。Random 作基本基準，穩定版本／設定用於退步比較。
- 評分拆成特徵、權重與分項輸出，固定白方視角與 pawn 分數單位。預設維持 material + PST；新特徵須定義單位、方向、適用階段及重複計分風險。
- 對戰保存實際玩家使用的完整評分／搜尋設定與版本，名稱不能代替數值；格式擴充須明確處理舊資料相容。
- 一次只比較一組特徵或少量相關權重，固定其他條件。實作正確、搜尋成本與棋力效果分別判斷；先做手動小實驗，再評估自動調參。
- 開局庫屬選步來源，採先查庫、未命中再搜尋的獨立流程，不列入靜態評分項。

### P5-UI1 比較結果檢視

- **目的／狀態：** 待實作。先讓既有比較結果能由 UI 查找與檢視，作為主要入口的第一步。
- **相依與範圍：** 讀取既有 `comparison.json` 與批次／棋譜資料，新增獨立「棋力比較」模式；顯示雙方實際評分／搜尋設定、預算、起始局面、勝和敗、未完成數、得分率與耗時。棋局清單接入既有回放；分類沿用批次資料與中繼資料，不另建一套對局目錄。
- **驗收：** 統計固定以候選方為視角，得分率為 `(勝 + 0.5 × 和) / 正常完成局數`，零局時顯示無資料；未完成不算和棋。舊版本、缺漏或損壞資料須明確標示可用欄位／錯誤，不補造設定或數值；一般批次及回放仍可用。
- **界線：** 第一版顯示結果摘要與勝和負分布；未保存的逐局時間／節點資訊不推測。Elo、信賴區間與自動判定提升留待統計分析階段，不因得分率超過 50% 宣稱變強。

### P5-UI2 啟動與控制比較

- **目的／狀態：** 待實作。從 UI 完成設定、執行、保存與查看結果；不要求使用者先下 terminal 指令。
- **相依與範圍：** UI1 與 P5 固定深度比較；先選取既有評分設定檔，指定基準／候選、開局集、深度、對局數、種子與批次名稱／標籤，不同時製作完整權重編輯器。擴充共用比較服務的進度與合作式取消介面，由背景工作執行，CLI／UI 共用配對、規則、統計及保存流程。
- **驗收：** 同局面交換黑白，保存實際設定；兩個評分玩家沿用相同搜尋設定限制。UI 搜尋期間可回應，顯示已完成局／配對數、進行中與未完成數；停止後保存已完成結果，中斷的一局與不完整配對明列，停止不冒稱比較完成。以可控背景工作測試進度、取消、錯誤、保存與回放，不只測按鈕文字。
- **可視化：** 顯示勝和負分布及按完成配對更新的累積得分率，進行中的數值標示暫時結果。可選擇觀看棋局，但背景對戰不等待棋盤動畫；多開局比重複確定性 Alpha-Beta 的同一局面更有資訊，種子不代表能改變其選步。
- **界線：** 第一版只提供固定深度評分比較及停止，不混入固定時間、自動調參、一般真人對戰重做或搜尋演算法新增。暫停／續跑與多程序比較另按需求定義，不直接沿用一般批次控制語意。

### P5-T 固定時間比較

- **目的／狀態：** 尚未整合。在初輪固定深度實驗後，驗證相同時間預算下的評分成本與搜尋效果。
- **相依：** S3 核心時間／取消與現有固定深度比較已完成；接續 UI2，先定義獨立的時間預算模式、每步限制及深度上限語意。
- **範圍：** 接入比較 API／CLI／UI，雙方使用一致時間限制與搜尋選項，保存實際設定、最後完整深度、停止原因與耗時；一般深度、最深探索及 quiescence 延伸須分清。保留固定深度模式及舊資料讀取；UI 更新與棋盤動畫不得刻意延遲對戰流程。
- **驗收：** 不混用或誤標兩種預算；假時鐘／取消測試涵蓋逾時與未完成首輪，回傳合法備援且不冒稱完成指定深度；根棋盤不變、設定快照一致、配對及結果統計正確。合作式停止不能強制中斷 evaluator，實際耗時與結果不要求跨機器完全相同；報告硬體與並行條件。

### P5-S 搜尋設定比較與統計分析

- **目的／狀態：** 按需求另立任務，不是 UI 第一版的前置條件。
- **搜尋比較：** 現有 P5 評分比較要求双方搜尋設定一致；另定比較類型，允許指定搜尋選項差異並保存雙方實際設定，其餘評分、開局及預算一致。不取消既有評分比較的保護，也不把同深度耗時改善直接當成棋力提升；先比較設定開關，跨程式版本比較另定版本執行與識別方式。
- **統計分析：** 先定開局樣本、預定局數與結論規則，再以交換黑白的配對結果處理不確定性；不完整配對另列，不將同局面的確定性重複視為新增獨立樣本。信賴區間／相對 Elo 須保存方法與條件，樣本不足標示不足，不冒稱官方或真人 Elo。持續檢定、SPRT 等再獨立評估。
- **驗收：** 不同比較類型與允許差異清楚，預算與完整配對可追溯；用已知結果、零樣本、全部勝／負及中斷資料驗證統計邊界，不只驗證圖表顯示。

### UI 比較入口完成後：驗證 E1–E5 的棋力效果

- **目的／狀態：** 棋力效果待驗證。判斷候選特徵及權重是否值得採用，先從 E1 開始，再逐組評估；不因功能完成直接開啟預設。
- **相依：** P4、各評分項與 P5 Alpha-Beta 固定深度比較均已具備；主要操作接續 UI2，前期可先用 CLI。固定時間整合不是啟動本輪的前置條件。
- **範圍：** 固定程式版本、搜尋深度／選項、其他特徵與權重；預先選定起始局面及種子，交換黑白比較穩定設定與單組候選。先檢查流程，再跑完整對局，使用未參與調整的局面作獨立驗證。Random 僅作基本檢查，主要對照穩定版本。方法見 [手動比較流程](評分調整與實驗.md#手動比較流程)。
- **驗收：** 設定、預算、種子與對局可追溯；勝和敗與未完成分開，截斷／停止／失敗不算和棋；報告樣本範圍、耗時及結論限制，明確決定採用、保留關閉或繼續驗證。小樣本不足時維持「待驗證」，不以勝過 Random 或功能測試宣稱提升棋力。

| 開局庫：提供獨立選步來源 | 先定義資料來源、合法性、版本與選步政策，再接未命中時的搜尋 fallback | 命中走法合法、選擇可追溯，未命中／無效資料可回退搜尋，保存實際來源與設定 |

## P7 評估自動調參

- **目的／狀態：** 遠期待評估，尚未實作；評估能否比手動調整更有效，不恢復舊 ML 路線。
- **相依：** P5 比較工具與至少一輪穩定、可重現的 P6 手動實驗；先確認比較方法能辨識退步與收益。若採對戰調參，先具備符合實驗需求的預算與統計方法。
- **範圍：** 先定目標、少量參數、計算預算與資料分組，再選網格／逐項搜尋、對戰調參或教師評分等方法；使用同一比較服務、設定快照與結果格式，不另建對戰／統計核心，也不預先建立空框架。P7 若接 UI，另做調參設定與候選歷程，沿用比較結果頁。
- **交付順序：** 與 P5 UI 分開任務及 commit；P5 UI1／UI2 不包含自動生成候選、參數搜索或訓練。先驗證少量參數的自動實驗，再決定是否加入 UI 控制，不一次製作整套調參平台。
- **驗收：** 調整與驗證資料分離，若使用對局資料則按整盤分組；以獨立驗證及穩定版本對照評估收益，未完成對局不硬給和棋標籤。不只追求對 Random 的勝率，也不把原 evaluator 分數當標籤後宣稱學得更強棋力。證據不足時可決定不立項。
