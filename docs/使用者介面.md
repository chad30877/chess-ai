# 使用者介面（UI）

[回到專案總覽](../README.md)

整理日期：2026-09-09。依目前實作整理。

## 用途

一般啟動顯示模式首頁，不預選場次或自動落子。提供批次自動對戰、真人對 AI，以及按日期查找棋譜；`--replay` 保留直接開啟指定棋譜的方式。

## 啟動與模式流程

```text
一般啟動 → 首頁
           ├─ 批次自動對戰 → 白方、黑方、場間間隔、場次
           │                → 生成進度 → 查看本批次 → 選對局 → 播放
           ├─ 真人下棋 → 我方顏色、對手、落子間隔 → 下棋 → 保存／回放本局
           └─ 棋譜回放 → 選日期 → 選批次或非批次 → 選對局 → 播放

指定 --replay → 直接進入該棋譜回放
```

視窗預設 **1280×960**，可拖曳調整，最小 900×768。沿用 900×768 的版面比例，依視窗尺寸重新建立原生解析度字型、棋子與按鈕，置中保留邊界；不把整張小畫面放大。Windows 在建立視窗前啟用 DPI awareness，棋子由 python-chess 內建 SVG 直接渲染，明確縮放向量路徑以相容 SDL_image；不支援 SVG 的環境才退回既有 60×60 PNG。字型優先 Microsoft JhengHei，列表仍使用 SAN 與英文 Moves。

### 批次自動對戰

1. 白方與黑方可各自切換 Random／Greedy，同批固定顏色。CLI 原本交替顏色的行為不變。
2. 場間間隔預設 **0 秒**，可輸入非負秒數；場次預設 **20**，可輸入正整數。點數字欄位後 Ctrl+A 清空／全選輸入，Enter 確認；也可直接按開始。無效數值會提示，不建立批次。
3. 按「開始生成」建立獨立批次並鎖定設定。頁面只顯示狀態、目前第幾場、進度條及已保存場數，不繪製棋盤或逐手走法。
4. 進度以**已保存場數**計算，正在跑的場次直到保存完成才增加進度。場間間隔僅在兩場之間等待，不是每手動畫間隔。
5. 暫停／繼續（或 Space）在走法邊界生效，畫面不阻塞；不提供批次單步。正在計算的 AI 可完成計算，但暫停期間不再套用走法。暫停期間不計入場間等待。
6. 「停止並保存」保留已完成場次和當盤已落子的走法；在場間停止則不開新局。停止當盤以 `*` 保存，並不標成和棋。批次顯示 stopped，正常完成所有要求場次則為 completed。
7. 完成／停止後按「查看本批次」進入對局清單。若跨日，預先開啟該批最近一個開局日期，可按上一層改選其他日期。沒有已保存對局時不啟用此按鈕。

UI 目前只用一個背景 worker，無手數上限、預設不自動申請和棋；CLI 仍可指定程序數、手數上限、初始局面與申請和棋政策。名稱、標籤及進階參數不放在這次四欄設定介面，CLI 的選填名稱／標籤仍保留。

### 真人對 AI

選自己的顏色與 Random／Greedy 對手，落子間隔仍為 0.5／1／2 秒（預設 1 秒）。執黑會自動翻轉棋盤，先等白方 AI。開始後點己方棋子，再點合法目的格；黃色框是選取，綠色圓圈是合法落點。AI 回合與終局後禁止真人落子。

升變需選后／車／象／馬，可取消後重選；王車易位點王的目的格，吃過路兵交由共用棋規。停止後可回放本局或保存棋譜；不提供悔棋、棋鐘、認輸或真人對真人。

「匯出棋譜」會保存 `data/replays/<日期_六位流水號>.json`，回放選單歸「非批次」。本局重按保存使用同一檔，不重複建立。記錄對戰開始／結束時間、雙方、實際策略參數、一次種子、初始局面、走法、棋規政策、狀態與結果。日期不是使用檔案修改時間，也不保存 final_fen 或 null 上限。

真人停止為 stopped／user_stop／*；AI 錯誤為 failed／ai_error／*，錯誤原因只在失敗時保存。LiveSession API 的 max_plies 仍可用，但不是本次 UI 的設定項目。

### 離開與重新開始

進行中的批次按回首頁、重新開始或關閉視窗，會先暫停並確認；取消恢復先前狀態。確認後先停止與保存，完成才離開，不取消尚待執行的保存工作。執行中的 AI 沒有硬性中斷，可能要等該次選步返回。

真人對局進行中，或有走法尚未保存時，離開會提醒；確認後清除記憶體中的本局。重新開始回到同模式的設定畫面。Esc 返回首頁；在確認、升變或回放選單中則關閉該對話框。

## 目前運作流程：棋譜回放

### 批次查找規劃

**狀態：日期 → 批次／非批次 → 對局 → 播放已實作。** 進入回放模式直接開啟選單，不要求使用者選 JSON 檔名。

- 日期依每盤 started_at 換算為台北日期；同批跨午夜開局的對局分別列在各自日期下。單盤跨午夜結束仍歸開局日。
- 日期內列出批次編號（有 name 時附名稱）及「非批次」；下一層列時間、對戰編號、白方、黑方和結果。
- 選中一局後按「播放」，保留舊的左右鍵、Home／End、翻轉及點選走法功能。選單支援上一層、重新整理、滑鼠滾輪、Enter 播放、Backspace 上一層與 Esc 關閉。
- 批次索引讀 manifest 與 games，不載入 positions。只列 manifest.saved_games 已發布的前綴，確保不顯示正在寫入的尾端。選定後才載入該局走法。
- 獨立回放需讀 JSON metadata 建立索引。舊資料缺每盤日期／時區時放「日期不詳」，不以批次日期或檔案時間捏造日期；缺對手或編號時顯示未知。
- 壞索引、缺少棋譜、越出批次目錄的相對路徑會略過並提示筆數；若選定後棋譜被刪除或含非法走法，顯示提示並保留選單與先前回放。
- UI 查找範圍固定為專案 data/batches、data/replays。其他位置可用 `--replay` 直接開啟；自訂 CLI 批次根目錄目前沒有 UI 路徑設定。

### 勝負顏色

| 標記 | 顏色 | 語意 |
| --- | --- | --- |
| 勝 | 薄荷綠 | 該玩家獲勝，不綁定白棋、黑棋或 AI 名稱 |
| 敗 | 中性灰藍 | 該玩家落敗 |
| 和 | 中性灰藍 | 正常和棋，雙方皆標和 |
| 未完成 | 琥珀色 | 停止／截斷／無正式結果 |

同一 AI 對調黑白時，綠色仍只跟著勝方。選中列使用藍灰底與外框，避免和勝方顏色混淆；文字標記讓勝負不只靠顏色辨識。尚未定義輾壓／略勝的評估方式，也不靠手數或最終局面推測勝勢；未來可另加獨立標記。

### 棋譜格式

schema v2 保存 `schema_version, initial_fen, moves_uci, result, metadata`，初始局面加完整走法足以獨立回放。批次 metadata 有批次／對局編號、每盤時間、白黑方、狀態、結束原因與 rules；seed 在 games 保存，策略參數在 manifest。真人獨立棋譜沒有 manifest，因此另外保存一次種子與策略參數。完整欄位分工見 [自動對戰](自動對戰.md#批次資料規劃)。

舊無 schema_version 的棋譜與 v1 棋譜仍可讀。回放側欄顯示對手、台北日期時間、編號、結果與結束原因，不顯示原始 JSON 路徑。內建六手範例仍可由「範例棋譜」載入；檔案版本缺每盤日期，列於日期不詳。

## 共用棋規規劃

**必要接點已完成。** 棋譜驗證、真人落子與 AI 對局都經 `engine/game.py`，底層維持 chess.Board。ReplaySession 保留走法堆疊，跳步與 current_board() 仍有對應歷史；FEN 快取只供顯示，初始 FEN 以前的歷史無法推導。

回放 current_outcome()／current_result() 按 metadata.rules.claim_draw 判定當前局面，舊資料缺此欄位時為 False。顯示的原始 result 仍保留，不強迫外部認輸棋譜或未完成範例符合棋規終局。自行產生的正常終局／截斷已有一致性驗證。

真人 LiveSession 的正式棋盤仍由主執行緒擁有，worker 取得 board.copy(stack=True)，停止或換局後舊結果不能套入新棋局。批次 worker 自行擁有整盤棋盤，UI 只讀進度，不共享可修改棋盤。搜尋、評分權重及模型訓練未因 UI 修改。

## 執行方式

從專案根目錄執行，環境建立見 [README](../README.md#環境設定)：

```powershell
& "./.venv/Scripts/python.exe" -m apps.play_ui
```

保留直接回放：

```powershell
& "./.venv/Scripts/python.exe" -m apps.play_ui --replay data/replays/sample_replay.json
```
