# 使用者介面（UI）

[回到專案總覽](../README.md)

整理日期：2026-10-07。依目前實作整理。

## 用途

一般啟動顯示模式首頁，不預選場次或自動落子。提供批次自動對戰、真人對 AI、按日期查找棋譜與棋力比較結果檢視；`--replay` 保留直接開啟指定棋譜的方式。

## 啟動與模式流程

```text
一般啟動 → 首頁
           ├─ 批次自動對戰 → 一般對戰／評分比較 → 模式所需設定
           │                → 共用進度與停止 → 棋譜清單／比較結果 → 播放
           ├─ 真人下棋 → 我方顏色、對手、落子間隔 → 下棋 → 保存／回放本局
           ├─ 棋譜回放 → 選日期 → 選批次或非批次 → 選對局 → 播放
           └─ 棋力比較 → 選比較批次 → 結果／完整設定／差異 → 回放
                          └─ 新增比較 → 批次設定（預選評分比較）

指定 --replay → 直接進入該棋譜回放
```

視窗預設 **1280×960**，可拖曳調整，最小 900×768。沿用 900×768 的版面比例，依視窗尺寸重新建立原生解析度字型、棋子與按鈕，置中保留邊界；不把整張小畫面放大。Windows 在建立視窗前啟用 DPI awareness，棋子由 python-chess 內建 SVG 直接渲染，明確縮放向量路徑以相容 SDL_image；不支援 SVG 的環境才退回既有 60×60 PNG。字型優先 Microsoft JhengHei，列表仍使用 SAN 與英文 Moves。

### 批次自動對戰

1. 選「一般對戰」或「評分比較」，只顯示該模式的設定。兩者都按「開始生成」，共用背景派發、進度、停止、錯誤處理與逐局保存；啟動後不能切換模式或修改設定。背景不等待棋盤動畫，也不顯示正在搜尋的棋盤。
2. 一般對戰：白方／黑方各選 Random 或 Greedy，同批固定顏色；場次預設 20，需為正整數；場間間隔預設 0 秒，需為非負秒數。間隔僅在兩局之間等待。CLI 原本交替顏色的行為不變。
3. 一般對戰的「暫停／繼續」或 Space 在落子邊界生效；計算可先返回，但暫停期間不套用走法，不計入場間等待。評分比較沒有暫停按鈕，Space 不改變狀態；設定方式見下方[設定、啟動與控制比較](#設定啟動與控制比較)。
4. 進度以已保存局數計算，另顯示目前局、正常完成與未完成局；評分比較再列完整／不完整配對與候選得分率。停止保留先前棋局與當盤已落子的走法，不開下一局；停止局以 `user_stop`／`*` 保存，不標為和棋。
5. 「回放最近保存棋局」不影響背景工作，「返回批次」回進度頁。完成／停止後，一般對戰可查看本批次棋譜（跨日可換日期），評分比較轉到棋力比較結果頁；未保存任何棋局時不啟用一般批次棋譜清單。失敗保留此前成功保存的棋局並顯示錯誤。

一般批次沒有交換黑白配對與一致搜尋預算的驗證，不能事後冒稱公平棋力比較；保存格式及舊批次讀取不變。

### 真人對 AI

選自己的顏色與 Random／Greedy 對手，落子間隔仍為 0.5／1／2 秒（預設 1 秒）。執黑會自動翻轉棋盤，先等白方 AI。開始後點己方棋子，再點合法目的格；黃色框是選取，綠色圓圈是合法落點。AI 回合與終局後禁止真人落子。

升變需選后／車／象／馬，可取消後重選；王車易位點王的目的格，吃過路兵交由共用棋規。停止後可回放本局或保存棋譜；不提供悔棋、棋鐘、認輸或真人對真人。

「匯出棋譜」會保存 `data/replays/<日期_六位流水號>.json`，回放選單歸「非批次」。本局重按保存使用同一檔，不重複建立。記錄對戰開始／結束時間、雙方、實際策略參數、一次種子、初始局面、走法、棋規政策、狀態與結果。日期不是使用檔案修改時間，也不保存 final_fen 或 null 上限。

真人停止為 stopped／user_stop／*；AI 錯誤為 failed／ai_error／*，錯誤原因只在失敗時保存。LiveSession API 的 max_plies 仍可用，但不是本次 UI 的設定項目。

### 離開與重新開始

進行中的批次離開或關閉視窗會確認：一般對戰先暫停，取消恢復原狀；評分比較持續執行，取消不改變狀態。確認後等待停止與保存完成才離開，不取消排隊中的保存工作。一般 AI 可能需等選步返回；比較搜尋支援合作式取消，但單次 evaluator 呼叫不能強制中斷。完成後重新設定保留原批次模式。

真人對局進行中，或有走法尚未保存時，離開會提醒；確認後清除記憶體中的本局。重新開始回到同模式的設定畫面。Esc 返回首頁；在確認、升變或回放選單中則關閉該對話框。

### 棋力比較結果檢視

1. 首頁選「棋力比較」，列出 `data/batches` 下已保存的評分比較批次與名稱；按「重新整理」重讀結果。一般批次仍由原有棋譜回放入口查找。
2. 選批次後顯示基準／候選名稱、策略、固定一般搜尋深度、批次狀態、逐局耗時總和與棋局清單。統計及勝和敗分布固定以候選方為視角，不隨執白／執黑改變。
3. 勝和敗及未完成數仍涵蓋所有已保存棋局；完整配對得分率只用兩局皆正常完成的配對，計算 `(配對內勝局 + 0.5 × 配對內和局) / 配對內局數`。僅一局已保存、或有一局停止／截斷的配對另列不完整，不加入得分率；沒有完整配對顯示「無資料」。未完成局不算和棋，結果摘要不代表已證明棋力提升。
4. 「基準完整設定」、「候選完整設定」與「設定差異」顯示保存的實際評分與搜尋設定；差異省略玩家名稱，只列不同欄位，不用目前預設值補齊歷史資料。上一／下一頁或滾輪可讀完整內容。
5. 點選棋局進入既有回放；「返回比較」保留原批次與清單位置。結果頁按 Esc／Backspace 回批次清單，清單再按一次回首頁；設定頁則先回結果。
6. 比較摘要支援 schema v1／v2，與 manifest 設定、已發布 games 列及逐局結果互相核對。缺漏、損壞、未知版本或不一致資料明確提示，不補造統計；單局缺少棋譜仍保留結果並標示「棋譜缺漏」，停用播放。棋譜被刪除或含非法走法時，留在結果頁顯示錯誤。

比較可由批次設定入口或 [比較 CLI](評分調整與實驗.md#alpha-beta-固定深度比較) 產生。索引只讀 manifest、comparison 與已發布的 games 前綴，不載入 positions 或逐手棋譜；選定播放時才驗證棋譜。舊有缺少比較摘要的中斷批次仍會提示資料缺漏，其已保存棋局可從「棋譜回放」查找。

### 設定、啟動與控制比較

1. 首頁 → 批次自動對戰 → 評分比較；棋力比較的「新增比較」是同一入口的捷徑，預選評分比較，不另建表單或背景工作。
2. 點選基準／候選按鈕循環選 `configs/evaluation/*.json`，預設 stable.json 與 example_tapered.json；啟動時解析並固定設定，來源檔後續修改不影響本批次。
3. 開局集接受文字檔路徑，相對路徑以專案根目錄為準；每行合法 FEN，忽略空白及 `#` 註解。留白為標準開局。設定或開局無效時提示且不建立批次。
4. 設定 Alpha-Beta 一般深度、每局面配對數與非負種子；雙方搜尋選項一致，沿用排序、quiescence depth 4、置換表、PVS 與 aspiration window 1.0 的既有預設。總配對數為開局數乘每局面配對數，每對以相同種子交換黑白。手數上限留白為無上限，非負數為單局截斷上限；名稱與逗號分隔標籤選填。文字欄位 Ctrl+A 清空、Enter 確認、Esc 放棄編輯。和棋政策不自動申請。
5. 執行與控制由上方共用批次頁負責；評分比較不提供暫停／續跑。候選得分率只計兩局皆正常完成的配對，停止／截斷局與孤立單局另列，不算和棋。停止檢查對局邊界與搜尋節點，保存完成才可查看本批次結果。

比較服務的 `control`／`progress` 回呼仍供 API 使用，CLI 保留原本方式。比較摘要逐局原子更新，既有 schema v1／v2 仍可讀取；一般批次不新增比較摘要。目前只有一個背景 worker，多程序並行列為後續共用批次功能，每場搜尋維持單執行緒；權重編輯與固定時間另行安排。

人工檢查：`python -m apps.play_ui` → 批次自動對戰，確認兩種模式切換欄位；一般對戰測暫停／繼續／停止。評分比較用深度 1、配對數 1、手數上限 2 確認兩局保存、未完成與無得分率，再測停止、離開取消／確認、回放返回批次。首頁 → 棋力比較 → 新增比較應跳回同一批次設定；完成後檢視完整設定、差異及回放。

## 目前運作流程：棋譜回放

### 批次查找規劃

**狀態：日期 → 批次／非批次 → 對局 → 播放已實作。** 進入回放模式直接開啟選單，不要求使用者選 JSON 檔名。

- 日期依每盤 started_at 換算為台北日期；同批跨午夜開局的對局分別列在各自日期下。單盤跨午夜結束仍歸開局日。
- 日期內列出批次編號（有 name 時附名稱）及「非批次」；下一層列時間、對戰編號、白方、黑方和結果。
- 選中一局後按「播放」，保留舊的左右鍵、Home／End、翻轉及點選走法功能。選單支援上一層、重新整理、滑鼠滾輪、Enter 播放、Backspace 上一層與 Esc 關閉。
- 批次索引讀 manifest 與 games，不載入 positions。只列 manifest.saved_games 已發布的前綴，確保不顯示正在寫入的尾端。選定後才載入該局走法。
- 獨立回放需讀 JSON metadata 建立索引。舊資料缺每盤日期／時區時放「日期不詳」，不以批次日期或檔案時間捏造日期；缺對手或編號時顯示未知。
- 壞索引、缺少棋譜、越出批次目錄的相對路徑會略過並提示筆數；若選定後棋譜被刪除或含非法走法，顯示提示並保留選單與先前回放。
- UI 查找範圍固定為專案 data/batches、data/replays。其他位置可用 `--replay` 直接開啟；自訂 CLI 批次根目錄目前沒有 UI 路徑設定。

### 勝負顏色

| 標記 | 顏色 | 語意 |
| --- | --- | --- |
| 勝 | 薄荷綠 | 該玩家獲勝，不綁定白棋、黑棋或 AI 名稱 |
| 敗 | 中性灰藍 | 該玩家落敗 |
| 和 | 中性灰藍 | 正常和棋，雙方皆標和 |
| 未完成 | 琥珀色 | 停止／截斷／無正式結果 |

同一 AI 對調黑白時，綠色仍只跟著勝方。選中列使用藍灰底與外框，避免和勝方顏色混淆；文字標記讓勝負不只靠顏色辨識。尚未定義輾壓／略勝的評估方式，也不靠手數或最終局面推測勝勢；未來可另加獨立標記。

### 棋譜格式

schema v2 保存 `schema_version, initial_fen, moves_uci, result, metadata`，初始局面加完整走法足以獨立回放。批次 metadata 有批次／對局編號、每盤時間、白黑方、狀態、結束原因與 rules；seed 在 games 保存，策略參數在 manifest。真人獨立棋譜沒有 manifest，因此另外保存一次種子與策略參數。完整欄位分工見 [自動對戰](自動對戰.md#批次資料規劃)。

舊無 schema_version 的棋譜與 v1 棋譜仍可讀。回放側欄顯示對手、台北日期時間、編號、結果與結束原因，不顯示原始 JSON 路徑。內建六手範例仍可由「範例棋譜」載入；檔案版本缺每盤日期，列於日期不詳。

## 共用棋規規劃

**必要接點已完成。** 棋譜驗證、真人落子與 AI 對局都經 `engine/game.py`，底層維持 chess.Board。ReplaySession 保留走法堆疊，跳步與 current_board() 仍有對應歷史；FEN 快取只供顯示，初始 FEN 以前的歷史無法推導。

回放 current_outcome()／current_result() 按 metadata.rules.claim_draw 判定當前局面，舊資料缺此欄位時為 False。顯示的原始 result 仍保留，不強迫外部認輸棋譜或未完成範例符合棋規終局。自行產生的正常終局／截斷已有一致性驗證。

真人 LiveSession 的正式棋盤仍由主執行緒擁有，worker 取得 board.copy(stack=True)，停止或換局後舊結果不能套入新棋局。批次 worker 自行擁有整盤棋盤，UI 只讀進度，不共享可修改棋盤。搜尋、評分權重及模型訓練未因 UI 修改。

## 執行方式

從專案根目錄執行，環境建立見 [README](../README.md#環境設定)：

```powershell
& "./.venv/Scripts/python.exe" -m apps.play_ui
```

保留直接回放：

```powershell
& "./.venv/Scripts/python.exe" -m apps.play_ui --replay data/replays/sample_replay.json
```
