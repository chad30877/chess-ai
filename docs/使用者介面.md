# 使用者介面（UI）

[回到專案總覽](../README.md)

整理日期：2026-10-07。依目前實作整理。

## 用途

一般啟動顯示模式首頁，不預選場次或自動落子。提供批次自動對戰、真人對 AI 與統一的「對局紀錄」查找及檢視；`--replay` 保留直接開啟指定棋譜的方式。

## 啟動與模式流程

```text
一般啟動 → 首頁
           ├─ 批次自動對戰 → 一般對戰／評分比較 → 模式所需設定
           │                → 共用進度與停止 → 對局紀錄 → 播放
           ├─ 真人下棋 → 我方顏色、對手、落子間隔 → 下棋 → 保存／回放本局
           └─ 對局紀錄 → 日期篩選／分頁 → 比較、一般批次或非批次
                       → 結果／保存設定 → 點選棋局回放 → 返回原位置
                       └─ 新增比較 → 批次設定（預選評分比較）

指定 --replay → 直接進入該棋譜回放
```

視窗預設 **1280×960**，可拖曳調整，最小 900×768。沿用 900×768 的版面比例，依視窗尺寸重新建立原生解析度字型、棋子與按鈕，置中保留邊界；不把整張小畫面放大。Windows 在建立視窗前啟用 DPI awareness，棋子由 python-chess 內建 SVG 直接渲染，明確縮放向量路徑以相容 SDL_image；不支援 SVG 的環境才退回既有 60×60 PNG。字型優先 Microsoft JhengHei，列表仍使用 SAN 與英文 Moves。

### 批次自動對戰

1. 選「一般對戰」或「評分比較」，只顯示該模式的設定。兩者都按「開始生成」，共用背景派發、進度、停止、錯誤處理與逐局保存；啟動後不能切換模式或修改設定。背景不等待棋盤動畫，也不顯示正在搜尋的棋盤。
2. 一般對戰：白方／黑方各選 Random 或 Greedy，同批固定顏色；場次預設 20，需為正整數；場間間隔預設 0 秒，需為非負秒數。並行時每個執行席位保存一局後等待這段間隔，再接下一局；其他席位可繼續，等待不占用搜尋。CLI 原本交替顏色的行為不變。
3. 兩種模式共用「同時對戰場數」，初始預設 4，可輸入正整數；實際值取要求值、CPU 數、工作數的最小值（Windows 程序池上限 61）。一般對戰每個工作一局，比較每個工作一組交換黑白配對，組內兩局依序執行，不同組可並行。每場 Alpha-Beta 搜尋維持單執行緒；實際值為 1 時沿用協調端逐局執行，不另建程序池。
4. 一般對戰的「暫停／繼續」或 Space 暫停所有席位，在落子邊界生效；計算可先返回，但暫停期間不套用走法、不派發新工作、不累計場間等待。協調端仍保存已回報結果。評分比較沒有暫停按鈕，Space 不改變狀態；設定方式見下方[設定、啟動與控制比較](#設定啟動與控制比較)。
5. 進度以已保存局數計算，另顯示要求／實際程序數、等待／執行中／已結束工作及已回報局數、正常完成與未完成局。已結束工作包含中斷或失敗，不等同正常棋規終局；評分比較再列完整／不完整配對與候選得分率。停止保留先前棋局與當盤已落子的走法，不開下一局；停止局以 `user_stop`／`*` 保存，不標為和棋。
6. 「回放最近保存棋局」不影響背景工作，「返回批次」回進度頁。完成／停止後，兩種模式都轉到同一「對局紀錄」摘要頁；未保存任何棋局時不啟用一般批次棋譜清單。失敗保留此前成功保存的棋局並顯示錯誤。

存檔依回報順序連續發布，`games.csv.game_number` 與每日唯一 ID 保持既有格式；固定工作／邏輯棋局編號另外保存於棋譜 `metadata.execution`，種子由編號決定，不受完成順序影響。一般批次記錄 base_seed，比較沿用 pair seed 規則；舊批次不需要補欄位。

一般批次沒有交換黑白配對與一致搜尋預算的驗證，不能事後冒稱公平棋力比較；保存格式及舊批次讀取不變。

### 真人對 AI

選自己的顏色與 Random／Greedy 對手，落子間隔仍為 0.5／1／2 秒（預設 1 秒）。執黑會自動翻轉棋盤，先等白方 AI。開始後點己方棋子，再點合法目的格；黃色框是選取，綠色圓圈是合法落點。AI 回合與終局後禁止真人落子。

升變需選后／車／象／馬，可取消後重選；王車易位點王的目的格，吃過路兵交由共用棋規。停止後可回放本局或保存棋譜；不提供悔棋、棋鐘、認輸或真人對真人。

「匯出棋譜」會保存 `data/replays/<日期_六位流水號>.json`，對局紀錄標示「非批次」。本局重按保存使用同一檔，不重複建立。記錄對戰開始／結束時間、雙方、實際策略參數、一次種子、初始局面、走法、棋規政策、狀態與結果。日期不是使用檔案修改時間，也不保存 final_fen 或 null 上限。

真人停止為 stopped／user_stop／*；AI 錯誤為 failed／ai_error／*，錯誤原因只在失敗時保存。LiveSession API 的 max_plies 仍可用，但不是本次 UI 的設定項目。

### 離開與重新開始

進行中的批次離開或關閉視窗會確認：一般對戰先暫停，取消恢復原狀；評分比較持續執行，取消不改變狀態。確認後等待停止與保存完成才離開，不取消排隊中的保存工作。一般 AI 可能需等選步返回；比較搜尋支援合作式取消，但單次 evaluator 呼叫不能強制中斷。完成後重新設定保留原批次模式。

真人對局進行中，或有走法尚未保存時，離開會提醒；確認後清除記憶體中的本局。重新開始回到同模式的設定畫面。Esc 在紀錄設定頁先回摘要、摘要回清單、日期選單回清單，再返回來源畫面或首頁；確認與升變時取消該對話框。

### 棋力比較結果檢視

「棋力比較」與「棋譜回放」的查找入口已合併為首頁的 **對局紀錄**，三種資料使用同一清單、摘要、設定檢視與回放導覽。

- 比較批次：顯示候選／基準名稱、策略、固定一般深度、保存狀態與耗時；勝和敗分布以候選方為視角。完整配對得分率只計兩局正常完成的配對，孤立或停止／截斷局另列不完整配對，無完整配對顯示「無資料」。小樣本結果不代表已證明棋力提升。
- 一般批次：顯示保存的白黑方玩家、白勝／和／黑勝、未完成與結果缺漏數，不提供候選統計或配對得分率。
- 非批次：每份棋譜獨立列入清單，摘要使用其實際 metadata 與 result。設定、玩家、狀態或耗時缺漏時標示「未記錄」；日期缺漏列「日期不詳」，不推算耗時或補預設設定。

比較可檢視基準／候選完整設定、設定差異（省略名稱）及整批保存設定；其他資料共用「保存設定」。內容來自保存資料，來源設定檔後續修改不影響顯示。設定、清單與棋局皆支援分頁及滾輪。

比較摘要支援 schema v1／v2，核對 manifest 設定、已發布 games 與逐局結果。摘要缺漏、損壞或不一致時，仍列已保存棋局及原始設定，清楚標示比較摘要不可用，不補造比較統計。缺少棋譜的列保留結果並停用播放；選定後檔案消失或含非法走法則留在摘要顯示錯誤，保留先前可用回放。損壞索引或描述檔也留可見的資料問題項目。

點選棋局進入既有回放，「返回紀錄」保留原日期、批次、頁碼與選取位置；「返回紀錄清單」恢復原清單頁及選取列。從批次結果進入後可再返回批次；回放中的「選擇對局」使用同一頁，未匯出的本局仍須先保存。直接指定 `--replay` 的方式保持可用。

### 設定、啟動與控制比較

1. 首頁 → 批次自動對戰 → 評分比較；對局紀錄的「新增比較」是同一入口的捷徑，預選評分比較，不另建表單或背景工作。
2. 點選基準／候選按鈕循環選 `configs/evaluation/*.json`，預設 stable.json 與 example_tapered.json；啟動時解析並固定設定，來源檔後續修改不影響本批次。
3. 開局集接受文字檔路徑，相對路徑以專案根目錄為準；每行合法 FEN，忽略空白及 `#` 註解。留白為標準開局。設定或開局無效時提示且不建立批次。
4. 設定 Alpha-Beta 一般深度、每局面配對數與非負種子；雙方搜尋選項一致，沿用排序、quiescence depth 4、置換表、PVS 與 aspiration window 1.0 的既有預設。總配對數為開局數乘每局面配對數，每對以相同種子交換黑白。手數上限留白為無上限，非負數為單局截斷上限；名稱與逗號分隔標籤選填。文字欄位 Ctrl+A 清空、Enter 確認、Esc 放棄編輯。和棋政策不自動申請。
5. 執行與控制由上方共用批次頁負責；評分比較不提供暫停／續跑。候選得分率只計兩局皆正常完成的配對，停止／截斷局與孤立單局另列，不算和棋。停止檢查對局邊界與搜尋節點，保存完成才可查看本批次結果。

比較服務的 `control`／`progress` 回呼仍供 API 使用，CLI 保留原本方式。比較摘要逐局原子更新，既有 schema v1／v2 仍可讀取；一般批次不新增比較摘要。多程序由共用派發服務負責，最多派發實際 worker 數的工作；有界佇列最多容納 worker 數兩倍的回報，協調端持續保存，不等待整組配對完成。停止時不派新工作、合作式取消在途搜尋與對局，排空回報並關閉子程序後才離開。工作錯誤會停止其他工作，保留已取得結果及不完整配對；協調端保存失敗時排空佇列讓程序退出，僅已發布前綴可讀。權重編輯與固定時間另行安排。

人工檢查：`python -m apps.play_ui` → 批次自動對戰，確認兩種模式共用同時對戰場數（初始 4）；一般對戰以至少 8 局、4 個 worker 測暫停／繼續／停止及場間間隔。評分比較用深度 1、配對數 1、手數上限 2 確認兩局保存、未完成與無得分率，再測停止、離開取消／確認、回放返回批次。首頁 → 對局紀錄 → 新增比較應跳回同一批次設定；以至少 4 組配對確認多組同時執行，完成後檢視完整設定、差異及回放。執行時關閉視窗應等待保存並退出子程序，不重開 UI。

## 目前運作流程：棋譜回放

### 批次查找規劃

**狀態：已整合至對局紀錄。** 預設列全部資料；「日期：全部」可切換指定日期或「日期不詳」，日期選單與結果清單都有分頁及返回。

- 日期依每盤 started_at 換算台北日期；同批跨午夜開局可在不同日期找到，跨午夜結束仍歸開局日。篩選只限制下方棋局清單，批次統計與設定仍涵蓋整批，頁面明示篩選日期及局數。
- 批次只讀 manifest、comparison 與 games 已發布前綴，不載入 positions，點選後才驗證走法。非批次讀 JSON 建立索引；不使用檔名或修改時間補造對戰日期。
- UI 範圍固定為專案 data/batches、data/replays；其他位置使用 `--replay`。資料及保存格式不搬移、不重寫，查找不控制背景對戰。

### 勝負顏色

摘要分布保留綠色勝、灰色和、灰藍色敗；比較以候選方為視角，一般／非批次以白勝／和／黑勝標記。未完成、結果缺漏與棋譜問題另列文字，避免誤當和棋。選取列以按鈕反白表示，不推測輾壓／略勝。

### 棋譜格式

schema v2 保存 `schema_version, initial_fen, moves_uci, result, metadata`，初始局面加完整走法足以獨立回放。批次 metadata 有批次／對局編號、每盤時間、白黑方、狀態、結束原因與 rules；seed 在 games 保存，策略參數在 manifest。真人獨立棋譜沒有 manifest，因此另外保存一次種子與策略參數。完整欄位分工見 [自動對戰](自動對戰.md#批次資料規劃)。

舊無 schema_version 的棋譜與 v1 棋譜仍可讀。回放側欄顯示對手、台北日期時間、編號、結果與結束原因，不顯示原始 JSON 路徑。內建六手範例仍可由「範例棋譜」載入；檔案版本缺每盤日期，列於日期不詳。

## 共用棋規規劃

**必要接點已完成。** 棋譜驗證、真人落子與 AI 對局都經 `engine/game.py`，底層維持 chess.Board。ReplaySession 保留走法堆疊，跳步與 current_board() 仍有對應歷史；FEN 快取只供顯示，初始 FEN 以前的歷史無法推導。

回放 current_outcome()／current_result() 按 metadata.rules.claim_draw 判定當前局面，舊資料缺此欄位時為 False。顯示的原始 result 仍保留，不強迫外部認輸棋譜或未完成範例符合棋規終局。自行產生的正常終局／截斷已有一致性驗證。

真人 LiveSession 的正式棋盤仍由主執行緒擁有，worker 取得 board.copy(stack=True)，停止或換局後舊結果不能套入新棋局。批次 worker 自行擁有整盤棋盤，UI 只讀進度，不共享可修改棋盤。搜尋、評分權重及模型訓練未因 UI 修改。

## 執行方式

從專案根目錄執行，環境建立見 [README](../README.md#環境設定)：

```powershell
& "./.venv/Scripts/python.exe" -m apps.play_ui
```

保留直接回放：

```powershell
& "./.venv/Scripts/python.exe" -m apps.play_ui --replay data/replays/sample_replay.json
```
