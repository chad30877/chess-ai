## 介面與評分視角

- `engine/game.py`：包裝建立棋盤、取得合法走法、檢查走法後落子、判斷結束。主要規則來自 `chess.Board`。
- `engine/interfaces.py`：定義 `Player.choose_move(board)` 與 `Evaluator.evaluate(board)` 兩個協定，方便替換策略與評分器。

**評分固定使用白方視角：正分對白方有利，負分對黑方有利。** 不會因輪到黑方而自動翻轉符號。白方選高分、黑方選低分。

## 玩家策略

`engine/players.py` 提供：

| 玩家 | 選步方式 | 目前用途 |
| --- | --- | --- |
| `RandomPlayer` | 從合法走法隨機選一手 | 資料產生、UI 與對戰 CLI 的基準對手 |
| `GreedyPlayer` | 每個合法走法各試下一手；先套用共用終局分數，非終局才交給 evaluator，同分隨機選 | 資料產生、UI Demo 與現有對戰 CLI |
| `AlphaBetaPlayer` | 呼叫注入的 `Searcher`，使用回傳的 `best_move` | 多步搜尋的玩家介面；可用 `from_evaluator()` 快速建立 |

現在 `GreedyPlayer()` 的預設評分是 `HandcraftedEvaluator`（子力＋位置表）。但 `scripts/engine_match.py` 的 `material` 選項明確使用 `MaterialEvaluator`，只算子力。兩者目前不是相同設定。

## 評分器

- `engine/evaluation/evaluator.py`：`MaterialEvaluator` 計算白方子力減黑方子力；預設兵 1、馬 3、象 3、車 5、后 9。`HandcraftedEvaluator` 再加上 PST 位置分數。`evaluate_material()` 與 `evaluate()` 是函式形式的入口。
- `engine/evaluation/pst.py`：為六種棋子各定義一張 8×8 棋子位置表。例如馬在中央的分數較高。黑方以同檔、上下鏡射的白方表計分，再算白方總分減黑方總分。預設沿用這組表；E1 可選用中局／殘局平滑混合，殘局表只調整國王。
P1 已移除舊 ML 評分器與相容別名；子力、PST 與搜尋行為保持原樣。後續方向見 [評分調整與實驗](評分調整與實驗.md)。

## 搜尋流程與目前限制

- `engine/search/types.py`：`SearchLimits` 保存深度、正整數毫秒上限與停止 callback；`SearchResult` 回傳走法、白方視角分數、完成／探索深度、停止原因、節點／剪枝數、置換表命中／寫入數、PVS scout／重搜數及 aspiration／重搜數；`Searcher` 定義搜尋介面。
- `engine/search/alphabeta.py`：實作深度限制的 Minimax 與 Alpha-Beta 剪枝。白方最大化、黑方最小化。到達深度或終局才計分。
- `engine/search/terminal.py`：透過 `engine.game.get_outcome()` 判斷終局；Alpha-Beta 與 Greedy 共用相同的白方視角分數。將死使用約正負一百萬並依距離微調，和棋回傳 0。
- `claim_draw=False` 是預設政策；開啟後，可申請的三次重複與五十回合和棋也視為終局。資料生成、UI 對局與設定比較會把該盤規則傳入 Greedy；直接建立 Alpha-Beta 時可用同名參數指定。
- 搜尋與 Greedy 的分支使用 `board.copy(stack=True)`，保留重複局面判定所需的走法歷史；只修改分支副本，不 push/pop 呼叫者傳入的根棋盤。
- Alpha-Beta 預設啟用基本 move ordering：升變依升變棋子價值優先，其次是吃子並以 victim／attacker 子力值排序；同類型走法保持原有相對順序。可用 `move_ordering=False` 建立同深度未排序基準。
- 一般搜尋到達深度邊界後，預設再做最多 4 ply 的 quiescence，只延伸吃子與升變。非被將軍局面先以靜態分數作 stand-pat；被將軍時禁止 stand-pat，改搜尋全部合法應將。
- `quiescence_depth=0` 可完全停用 S2，供舊搜尋基準比較。已進入 quiescence 後若在硬上限仍被將軍，會再搜尋恰好一層合法應將，接著以終局或靜態分數停止，避免在受將局面直接估分，也確保延伸有限。
- 搜尋由 depth 1 逐輪迭代至 `max_depth`。`time_ms` 是整次呼叫的合作式 wall-clock 上限；`stop_requested` 可傳入零參數 callback（例如 `threading.Event.is_set`）要求取消。兩者在進入每個節點時檢查，不會強制中斷正在執行的 evaluator。
- 根局面尚未終局且正常完成迭代時，`completed_depth` 等於要求深度；逾時／取消時 `stop_reason` 分別是 `timeout`／`cancelled`，最佳走法與分數取最後完整輪次。若 depth 1 尚未完成，回傳一手合法的 depth 0 備援及根局面靜態分數。`depth_reached` 是實際走訪的最深 ply，包含未完成輪次與 quiescence；節點／剪枝數累計所有迭代。兩個深度沒有固定大小關係：所有分支提前終局時可完整完成深度 2 的迭代，但實際只走訪深度 1；不為了配合迭代深度補高 `depth_reached`。根局面已終局時兩者皆為 0。
- 每次 `search()` 預設建立一張新的置換表，同一次迭代加深可重用深度、分數、最佳走法及 EXACT／LOWER／UPPER 界限；較淺條目仍可提供第一優先走法。`transposition_hits` 包含這類排序命中，`transposition_stores` 是成功寫入／替換數。可用 `use_transposition_table=False` 關閉，取得無快取基準。
- 置換 key 除當前棋盤狀態外，包含五十回合計數、自上次不可逆走法起的完整局面歷史及 `ply_from_root`。這會犧牲部分可合併機會，但避免錯把重複和棋狀態或不同將死距離當成同一分數。表不跨公開搜尋保存，因此替換 evaluator 或搜尋設定後不會命中先前結果；被取消的未完成節點不寫入。
- 一般搜尋節點預設使用 PVS：第一手走完整視窗，其餘走法先以 alpha（白方最大化）或 beta（黑方最小化）附近的窄窗 scout。scout 若改善目前值但仍在父視窗內，才完整重搜；fail-low／fail-high 已足以判斷時不重搜。窄窗以 `math.nextafter()` 取得相鄰浮點值，避免假設 evaluator 只回傳整數。`pvs_scouts`／`pvs_researches` 記啟動次數，可用 `use_pvs=False` 回到標準逐手完整視窗。
- 迭代加深從 depth 2 起，預設以上一個完整深度分數的正負 1 pawn 作 root aspiration window。結果必須嚴格位於兩界之間；落在外側或剛好等於邊界都只代表 bound，會立即用完整視窗重搜一次。`aspiration_searches`／`aspiration_researches` 記啟動次數；`aspiration_window` 可設正有限浮點數，或用 `None` 停用。重搜若逾時／取消，仍回傳上一個完整迭代。
- `max_depth` 以 **ply（半回合：任一方走一手）** 計算。深度 2 表示看自己一手及對手一手。

目前的限制：

- 尚無 history heuristic、LMR／Null move 或置換表容量淘汰；quiescence 目前不搜尋一般 checking moves，也沒有 delta pruning。PVS 只套用一般搜尋層，aspiration 失敗直接回到完整視窗而不逐次放大，置換表僅存在於單次 `search()`，不跨設定或對局持久化。

## 使用方式

在專案根目錄、已安裝依賴的 Python 環境中執行以下程式。環境設定見 [README](../README.md#環境設定)。

對戰 CLI 目前只有 `material` 與 `random`，沒有 `alphabeta`。可在 Python 中直接使用：

```python
import chess
from engine.evaluation.evaluator import HandcraftedEvaluator
from engine.search import AlphaBetaSearcher, SearchLimits

board = chess.Board()
searcher = AlphaBetaSearcher(
    evaluator=HandcraftedEvaluator(),
    limits=SearchLimits(max_depth=6, time_ms=500),
)
result = searcher.search(board)
print(
    result.best_move,
    result.score,
    result.completed_depth,
    result.transposition_hits,
    result.pvs_researches,
    result.aspiration_researches,
    result.stop_reason,
)
```

## 與共用棋規的關係

`engine/game.py` 持續以 `chess.Board` 提供合法走法、落子與 `claim_draw` 終局政策；`engine/search/terminal.py` 只負責把同一結果映射為搜尋分數。生成器仍僅使用 Random／Greedy，UI 也尚未提供 Alpha-Beta；真人模式由背景執行緒選步、主執行緒落子，批次模式在背景 worker 執行整盤並保存。

Alpha-Beta、Greedy 與對局層現在使用同一個申請和棋布林政策；分支以完整 move stack 判斷重複。搜尋深度與時間預算仍屬搜尋限制，不是整盤棋的勝負規則。

整體分工見 [README](../README.md#共用棋規與資料分類規劃)。

## E1 分階段評分

`EvaluationConfig(phase_enabled=True)` 啟用；預設 `False` 保持原有 material + PST。`piece_values` 與 `pst_weight` 為中局權重；`endgame_piece_values` 與 `endgame_pst_weight` 為殘局權重。省略殘局子力值時複製中局值，殘局 PST 倍率預設 1。兩階段共用 material／PST 開關。

階段模型 v1 固定計算雙方剩餘馬／象各 1、車 2、后 4 單位，`mg = min(剩餘單位, 24) / 24`，`eg = 1 - mg`。兵與王不計，升變後超過 24 則截至 1；輪到哪方、可調子力價格與走法歷史不影響比例。總分為 `mg × 中局加權分數 + eg × 殘局加權分數`，每階段先乘自己的倍率再混合，沒有硬切換門檻。

中局 PST v1 完全沿用；殘局 PST v1 只有國王改為中央活動獎勵（中央最高 +0.25、角落 -0.30 pawn），其餘表相同。初始兩階段子力值相同；這些是未經棋力實驗的保守起點，不宣稱最佳權重。國王 PST 仍可能與未來國王安全／活動力重複貢獻。

E1 的 schema v2 序列化 phase 開關／模型版本、兩套子力值及 PST 倍率／表版本。E5 後輸出為 v6，仍讀取 v1–v5；v1 載入後分階段關閉，v2 保留原有階段設定，兩者兵形皆關閉。舊版程式無法讀取 v6，重跑需使用相符版本。`stable.json`、`example_pst_half.json` 保留 v1，`example_tapered.json` 保留 v2 範例以驗證相容。

`evaluate_breakdown()` 啟用時回傳 `phase` 比例與 `stage_terms` 的中局／殘局原始值、權重、開關、貢獻。頂層 `terms` 則保存各項已加權混合的 raw_value、weight=1 與 contribution（關閉時 contribution=0），加總等於 total_score；要查看未乘倍率的原始 PST，使用 `stage_terms`。關閉時原有 terms 語意保持，phase 為 null、stage_terms 為空。

驗收涵蓋初始／純兵／升變上限、部分子力比例、兩階段不同倍率的手算公式、等步長階段變化、鏡射反號、開關及根棋盤歷史不變；另驗證 v1／v2 往返、非法設定、實際玩家及 P5 批次／CLI 保存。完整 165 個測試通過。

比較計畫：先以相同初始局面、種子與交換黑白對照穩定設定及 [分階段候選](../configs/evaluation/example_tapered.json)，固定現有 P5 的 Greedy 一手深度。先檢查可重現與保存，再用事先選定的中局／殘局局面做完整對局，分別報告勝和敗與 unfinished；獨立驗證局面不得拿來調權重。Alpha-Beta 固定深度比較已整合，使用方式見 [實驗文件](評分調整與實驗.md#alpha-beta-固定深度比較)。

```powershell

```

## E2 兵形評分

`engine/evaluation/pawn_structure.py` 定義 pawn feature v1，計算只依當前兵的位置，不依輪到哪方或合法走法。三項各有獨立 `PawnTermConfig(enabled, weight, endgame_weight)`，預設皆關閉；有限非負權重的單位為 pawn／特徵單位。Python 可用 `EvaluationConfig(pawn_terms={"isolated_pawns": PawnTermConfig(True, 0.15, 0.20)})` 啟用單項，省略的項目維持預設關閉。

| 特徵 | 定義與原始值方向 | 初始中局／殘局權重 |
| --- | --- | --- |
| isolated_pawns | 己方相鄰檔完全沒有己兵，無論其所在排；同檔的兵不解除孤立。原始值為黑方孤兵數減白方孤兵數 | 0.15／0.20 |
| doubled_pawns | 每檔 `max(兵數 - 1, 0)`，兩兵罰一單位、三兵罰兩單位；原始值為黑方額外兵數減白方額外兵數 | 0.10／0.15 |
| passed_pawns | 前方同檔／相鄰檔沒有敵兵，且同檔沒有己兵在前；只算該檔最前方符合資格的兵。原始值為白方推進單位總和減黑方推進單位總和 | 0.05／0.10 |

「前方」是白方較高排、黑方較低排，嚴格排除相同排；a/h 檔沒有環繞。通路兵推進單位為相對排減 1，合法兵在相對第 2／3／4／5／6／7 排分別得 1／2／3／4／5／6；兵升變後不再屬於此特徵。為方便除錯非法局面，推進單位限制在 0–6。通路資格不考慮其他棋子的阻擋、敵方攻擊或是否能立即推進，不代表必然能升變。內部結構結果另保留通路兵數供測試與除錯。

正的權重配合上述原始值，白方孤兵／疊兵較多時扣分，白方通路兵推進較多時加分。三項可以同時貢獻：孤立疊兵會同時受兩項懲罰，孤立通路兵可同時受罰與獎勵；通路兵的推進獎勵也可能與兵 PST 重疊。初始權重是待實驗的起點，並非已證明較強的設定。

分階段關閉時使用各項 `weight`，即使局面為殘局也不自動切換；啟用 E1 時以相同 raw_value 分別乘中局／殘局權重，再依 E1 比例混合。一般 `terms` 或分階段的 `stage_terms` 保存三項原始值、權重、開關、貢獻、單位與重疊風險；關閉仍計算原始值，貢獻為零。分階段頂層 terms 保持 E1 的已加權混合語意，原始數量需查看 stage_terms。

E2 的設定 schema v3 在 `terms` 加入上述三項，各保存 `enabled`、`weight`、`endgame_weight` 與 `feature_version=1`。拒絕未知項目、缺漏欄位、未知特徵版本、非布林開關或非法權重。讀取 v1／v2 時兵形關閉，保留原有分數；E5 後批次／CLI 保存實際注入玩家的完整 v6 設定。搜尋與 UI 操作不變。

E2 新增 15 個案例，涵蓋檔邊界、不同排的相鄰己兵、三重疊兵、雙方通路方向、前方敵兵與己兵、推進單位、鏡射反號、獨立權重／開關、階段端點／混合、根棋盤歷史、v1／v2 相容及 v3 往返／驗證，並驗證 Greedy 實際採用通路兵獎勵。P5 測試改用啟用三項兵形的候選，涵蓋 CLI 保存與種子重現；完整 180 個測試通過。

比較計畫：以 [E1 分階段設定](../configs/evaluation/example_tapered.json) 為 baseline、[E2 兵形候選](../configs/evaluation/example_pawn_structure.json) 為 candidate，讓兩方具有相同 E1 設定，只新增三項兵形。先用短局檢查流程，再以預先選定的兵形中局／殘局進行交換黑白的完整對局，固定種子與現有 Greedy 一手深度，報告勝和敗、unfinished 與耗時；用獨立局面驗證權重選擇。這一輪完成的是功能驗收，尚未執行棋力實驗。

```powershell

```

## E3 活動力評分

Mobility feature v1 採用「攻擊空間」：逐枚棋子計算幾何攻擊格，排除己方占據的目的格，再把同一棋種各棋子的格數相加。白方總數減黑方總數為 raw_value，正值配合非負權重對白方有利；始終計算雙方，與輪到哪方無關。這不是合法走法數或安全活動力。

- 兵計斜前方攻擊格，即使該格為空；不計前進一／兩步，升變走法不另外倍增，吃過路兵也不另加一格。
- 馬按跳躍目的格計數，不受途中棋子阻擋；象／車／后沿線直到第一枚棋子，敵方所在格算一格，己方所在格不算，後方格不算。
- 王計相鄰格，不檢查敵方攻擊或兩王距離，不加入易位；因此王的活動力不是王的合法移動能力。
- 受釘住的棋子仍按幾何攻擊格計分，被將軍時也不限制為應將走法。模型不衡量每格是否安全。
- 同一格被兩枚己方棋子攻擊，逐枚各算一次；它衡量棋子活動總量，而非整方攻擊格聯集。

六項 `MobilityTermConfig(enabled, weight, endgame_weight)` 各有獨立開關及權重，預設全關。省略的項目維持預設關閉；權重必須有限非負，單位為 pawn／攻擊目的格。

| 設定項目 | 初始中局／殘局權重 |
| --- | --- |
| pawn_mobility | 0.01／0.01 |
| knight_mobility | 0.03／0.03 |
| bishop_mobility | 0.03／0.03 |
| rook_mobility | 0.02／0.03 |
| queen_mobility | 0.01／0.02 |
| king_mobility | 0.01／0.02 |

例如 `EvaluationConfig(mobility_terms={"knight_mobility": MobilityTermConfig(True, 0.03, 0.03)})` 只啟用馬。分階段關閉使用 weight；啟用 E1 時 raw_value 在兩階段相同，各自加權後依 E1 比例混合。一般 terms／stage_terms 提供原始格數差、權重、開關、貢獻、單位及重疊風險；關閉仍提供原始值，貢獻為零。分階段頂層 terms 為已加權混合值、weight=1，單位為 pawn；查看原始格數需使用 stage_terms。

活動力與 PST 的中央化獎勵、兵攻擊格及未來國王安全可能重複貢獻。上述權重只是尚未驗證的起點；尤其 king_mobility 不具安全過濾，不當成國王安全特徵。此輪不改搜尋或既有 PST。

E3 的設定 schema v4 在 terms 新增六項，各保存 enabled、weight、endgame_weight、feature_version=1。嚴格驗證缺漏／未知欄位、未知特徵版本及非法值。v1–v3 JSON 可讀取，活動力關閉並保留舊階段／兵形設定及分數；`example_pawn_structure.json` 保留 v3 作相容範例，E5 後序列化與保存一律使用 v6。舊版程式不能讀取 v6，重現需使用相符程式版本。

E3 新增 12 個案例，涵蓋六棋種中央／角落手算、阻擋／吃子、馬跳躍、兵斜格、釘住／受將與王的不安全目的格、逐枚累加、雙方鏡射與輪次、階段端點／混合、獨立權重／開關、根棋盤歷史、v1–v3 舊分數與 v4 往返／驗證；Greedy 案例確認活動力會影響實際選步。更新 P5 比較保存／CLI 測試，完整 192 個測試通過。

## E4 國王安全評分

King safety feature v1 只使用當前王位、兵的位置與棋盤攻擊關係，不使用易位權或走法歷史推測是否曾易位。三項預設關閉，各有 `KingSafetyTermConfig(enabled, weight, endgame_weight)`；有限非負權重的單位為 pawn／特徵單位。

| 項目 | 定義與原始值方向 | 初始中局／殘局權重 |
| --- | --- | --- |
| king_pawn_shield | 王前方一排、同檔及相鄰檔的己兵數，白方減黑方；其他排的兵不算，a/h 檔只看兩檔 | 0.10／0 |
| king_zone_attacks | 王所在格與相鄰棋盤內格形成王區，遭對方攻擊的格數，黑方減白方；每格只算一次，包含被己方棋子占據的格 | 0.05／0 |
| king_file_exposure | 王所在檔及相鄰檔：有己兵則 0，無己兵但有敵兵為半開放 1，完全無兵為開放 2；各檔相加後取黑方減白方 | 0.08／0 |

前方對白方為較高排、黑方為較低排；王若已在其前進方向最末排，兵盾為 0。開放檔看整檔的兵分布，不要求敵車／后存在，也不受其他棋子阻擋影響，因此是檔暴露風險特徵，而非目前能被車直接攻擊的證明。若除錯局面缺少一方王，該方三項原始特徵皆為零。

王區攻擊使用當前棋盤占據情況，滑行攻擊遇第一枚棋子停止；受釘住的攻擊者仍算幾何攻擊，不要求其存在合法吃子走法。多枚攻擊者攻擊同格只算一次，與 E3 的逐枚累加活動力不同。評分不預測挪動國王後的攻擊，也不當作合法應將或安全走法判斷。

例如 `EvaluationConfig(phase_enabled=True, king_safety_terms={"king_pawn_shield": KingSafetyTermConfig(True, 0.10, 0)})` 只啟用兵盾並使用 E1 階段混合。預設殘局權重為零，三項中局貢獻隨 E1 中局比例平滑淡出，純殘局不抑制 E1 的王中央活動獎勵。可以另設非零殘局權重，但那是新的實驗選擇；若 phase_enabled=False，沿用既有規則只用中局權重，並不自動淡出。

分項保持一般 terms／stage_terms 的原始值、權重、開關、貢獻、單位及重疊風險；關閉時原始值保留而貢獻為零。E1 啟用時先分階段加權，再混合；頂層 terms 的 raw_value 為已加權混合值、weight=1，查看原始數量使用 stage_terms。兵盾／開放檔可能與兵形及兵 PST 重疊，王區攻擊可能與活動力及王 PST 重疊；權重尚未經棋力驗證。

E4 的設定 schema v5 新增三項完整設定與 feature_version=1，拒絕缺漏／未知欄位、未知版本、非法開關與權重。可讀取 v1–v4，國王安全保持關閉，原有階段、兵形、活動力與分數保持；`example_mobility.json` 保留 v4 作相容範例。E5 後輸出／保存使用 v6，重現需使用相符程式版本。

E4 新增 13 個案例，涵蓋兵盾位置／方向／邊界、開放與半開放檔、王區手算及去重、受釘住攻擊者、缺王、輪次／易位權／鏡射／歷史、獨立開關與權重、階段端點／混合、殘局王活動、v1–v4 舊分數及 v5 往返／驗證；P5 批次／CLI 測試使用實際啟用三項安全特徵的候選。完整 205 個測試通過。

比較計畫：以 [E3 設定](../configs/evaluation/example_mobility.json) 為 baseline、[E4 候選](../configs/evaluation/example_king_safety.json) 為 candidate，維持相同階段／兵形／活動力，只新增國王安全。固定起始局面、種子與 Greedy 一手深度交換黑白；短局只檢查流程，再以預先選定的王翼兵盾、開放檔中局及王活動殘局做完整對局，報告勝和敗、unfinished 與耗時，使用獨立局面驗證。此輪尚未執行棋力實驗。

```powershell

```

## E5 棋子協調評分

Coordination feature v1 新增三項，原始值一律為白方減黑方，正值配合非負權重對白方有利。只依目前棋子與兵的分布，與輪到哪方、走法歷史及合法活動空間無關。

| 項目 | 定義 | 初始中局／殘局權重 |
| --- | --- | --- |
| bishop_pair | 同一方至少有一枚白格象及一枚黑格象時為 1，否則為 0；每方最多一份獎勵 | 0.30／0.40 |
| rook_open_file | 車所在整檔完全沒有雙方兵，逐枚車計一單位 | 0.15／0.20 |
| rook_half_open_file | 車所在整檔沒有己兵、但至少有一枚敵兵，逐枚車計一單位 | 0.10／0.15 |

雙象按象所在格的顏色覆蓋判斷，不只按象的數量；多枚同色象不獲獎勵，升變象照相同規則計算，額外異色象不重複獲獎勵。車的開放／半開放檔互斥，有己兵的檔兩項皆不計；兵在車前方或後方都會影響整檔分類，同檔兩車逐枚計分，升變車不排除。非兵棋子阻擋不改變分類，這些是檔結構特徵，不表示車有直接攻擊或暢通的合法走法。

各項用 `CoordinationTermConfig(enabled, weight, endgame_weight)` 獨立設定，預設全關，權重必須有限非負。例如 `EvaluationConfig(coordination_terms={"bishop_pair": CoordinationTermConfig(True, 0.30, 0.40)})` 只啟用雙象；省略項目保持預設關閉。關閉 E1 時只使用中局 weight；啟用 E1 時每項先依中局／殘局權重計分，再平滑混合。分項保留原始值、權重、開關、貢獻、單位與重疊風險；關閉項目貢獻為零但保留原始值，分階段頂層 terms 沿用已加權混合語意。

雙象可能與象 PST／活動力重複貢獻，車的檔獎勵可能與車 PST、活動力、兵形及 E4 檔暴露重疊。同檔多車獎勵是本模型的明確選擇，權重需由獨立對戰評估；本輪不新增連車、車在第七排等其他協調特徵，也不改搜尋。

設定 schema v6 保存三項 enabled、weight、endgame_weight 與 feature_version=1，嚴格拒絕未知／缺漏欄位、未知版本、非法權重及開關。讀取 v1–v5 時協調三項關閉，既有階段／兵形／活動力／國王安全的設定與分數保持；輸出與保存一律 v6。`example_king_safety.json` 保留 v5 作相容基準，舊程式無法讀取 v6，重現需相符版本。
