# 專案搬移

本機專案位於 `D:\Projects\chess-ai`，從此目錄執行 `.venv\Scripts\python.exe -m apps.play_ui`。

研究資料中的絕對路徑可能參與內容身分雜湊；搬移已有研究結果的專案時，不可直接全域取代文字。`scripts.relocate_project_data` 會從原內容確認雜湊規則，再依相依關係更新內嵌快照、教師標記、學習成果、比較計畫及棋譜工作身分。實驗 UUID、候選數值及已完成棋局保持不變。決策見 [ADR](adr/0001-relocation-identities.md)。

## 操作順序

1. 停止研究工作及應用程式，記錄已安裝套件版本，完整複製專案至新位置。保留來源至全部驗證完成；不要共用同一份資料的硬連結。
2. 在新位置重建 `.venv`，使用相同 Python 與套件版本。依賴及快取留在專案內。
3. 從原專案執行 `python -m scripts.relocate_project_data --root <來源> --verify --report <搬移前報告>`，記錄正式讀取入口的驗證與進度。
4. 從新專案執行 `python -m scripts.relocate_project_data --root <新位置> --source <來源> --destination <新位置> --report <遷移規劃>`。預設只規劃；確認後加 `--apply` 寫入目的地副本。請將參數替換為完整路徑，並指定該專案的 Python。
5. 從新專案執行同一個 `--verify` 指令，輸出另一份報告並與搬移前報告比較。確認現存資料中的來源路徑已清除，且原始素材、棋譜走法、教師分數與候選數值不變。
6. 讓原位置暫時無法存取，從新位置啟動介面，開啟既有教師評分、學習成果、比較紀錄及棋譜。確認後才移除原目錄與暫存副本，並更新編輯器及 Codex 的專案入口。

工具處理 `data/`、`configs/` 的 JSON 與根目錄 `experiments.json`；其他文件、編輯器設定、快取及已提交 Git 歷史不在工具改寫範圍。未知研究類型、損壞的封印、索引碰撞或雜湊歧義會報錯；不要略過驗證後刪除來源。套用中若失敗，捨棄目的地資料副本並重新複製來源，再重新規劃，不在部分寫入的資料上重試。

## 人工檢查

從新位置啟動介面，依序查看「學習實驗」的既有成果與「比較紀錄」，開啟一盤已保存棋譜並前後播放；確認候選名稱、完成數及對局結果與搬移前一致。未完成研究仍由使用者手動決定是否續跑，搬移本身不啟動正式長實驗。
