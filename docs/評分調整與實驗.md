## 方向與目前實作

已完整移除舊的「774 維棋盤特徵 → 最終勝負分類」ML 路線，不保留舊 ML baseline 或相容別名。

目前 `EvaluationConfig` 統一保存兵／馬／象／車／后價值、material／PST 開關、PST 倍率與版本；`HandcraftedEvaluator` 提供可加總的分項輸出。尚無參數搜尋或新特徵學習。Random 保留為基本基準；穩定版本／權重設定另作退步比較，不需要保留舊 ML。

舊特徵／訓練程式、ML evaluator、模型與指標產物已刪除；`scripts/engine_match.py` 現在接受 `random`／`material`，舊 `ml` 與 `--ml-model` 明確報錯。現有 CSV、JSONL、棋譜與批次資料保留為通用對局紀錄。

## 特徵與權重規劃

評分拆成「特徵計算 → 權重設定 → 加權分數及分項說明」。特徵與計算定義見 [搜尋與評分](搜尋與評分.md#評分擴充規劃)。

| 層次 | 規劃 |
| --- | --- |
| 原始特徵 | 明確定義孤兵數差、活動力差等單位；收益固定白方減黑方，缺陷改用黑方減白方配合非負懲罰權重 |
| 設定 | 棋子價值、PST 倍率、各項權重／開關與設定版本 |
| 分項輸出 | 特徵原始值、使用權重、加權貢獻與總分，可供測試與除錯 |
| 保存 | 對戰保存實際使用的完整設定；名稱只供查找，不代替數值 |

第一版已維持預設兵值 1 的現有尺度與固定 PST 表內容，並提供 PST 倍率、項目開關與版本化往返。預設設定重現目前 material + PST；棋子價值仍可設定，但第一輪調參應固定子力價值，只調少量位置特徵。不要同時調整等價的多層倍率，避免無法辨識真正有效的參數。

例如總分可由「子力分數 + PST 倍率 × PST 分數 + 孤兵權重 × 孤兵數差 + …」組成。這是接口形式，不是已確定的權重值。每項需要記錄單位、正負方向、適用階段及可能重複計分的特徵。E1 已實作可選中局／殘局雙權重與平滑混合，預設關閉；設定與比較計畫見 [分階段評分](搜尋與評分.md#e1-分階段評分)。

E2 已新增孤兵、疊兵及含推進單位的通路兵，三項預設關閉，獨立保存中局／殘局權重及特徵版本。應以 E1 相同設定作對照，避免把階段與兵形效果混在一起；定義、限制與成對比較計畫見 [兵形評分](搜尋與評分.md#e2-兵形評分)。

E3 已新增六棋種幾何攻擊空間活動力，預設關閉，schema v4 保存各項完整權重及版本。以相同 E2 設定為對照，一次只加入活動力；模型不過濾釘住或不安全格，其影響需獨立評估。定義與比較方案見 [活動力評分](搜尋與評分.md#e3-活動力評分)。

E4 已新增兵盾、受攻擊王區及開放檔暴露，預設關閉且殘局權重為零，schema v5 保存完整設定。與 E3 相同設定比較，保持其他特徵固定；透過 E1 淡出安全貢獻，另檢查殘局王活動。定義與比較方案見 [國王安全評分](搜尋與評分.md#e4-國王安全評分)。

E5 已新增異色格雙象與車的互斥開放／半開放檔獎勵，預設關閉，schema v6 保存完整設定；應與相同 E4 設定比較，只增加協調項。E1–E5 功能已實作，仍須固定特徵定義與其他權重，分項檢查重複貢獻並執行獨立對戰。定義與比較方案見 [棋子協調評分](搜尋與評分.md#e5-棋子協調評分)。

`strategy_config()` 已改從實際玩家的 evaluator 讀取設定；CLI 批次、UI 批次與真人棋譜保存的完整數值／版本和下棋所用設定來自同一來源。

## 手動比較流程

P5 已實作以下流程。每個 initial FEN 與 repetition 組成一對，兩盤使用相同 pair seed 並重設亂數來源，第一盤 baseline 執白、第二盤 candidate 執白。批次 manifest 保存雙方實際 evaluator 設定、起始局面、重複次數、種子推導與預算；`comparison.json` 保存每一對的棋局 ID、顏色、結果、終止原因、耗時及雙方統計。

1. 固定一份穩定設定與程式版本，保留比較紀錄。
2. 一次只調整少量相關權重或加入一組特徵。
3. 使用相同起始局面交換黑白對戰；固定搜尋演算法、深度／時間限制與種子安排。
4. 記錄勝和敗、未完成數量、耗時及必要的節點數，並執行戰術／特徵測試。
5. 另用未參與調整的起始局面驗證；結果不足時記為待驗證，不宣稱棋力提升。

比較 evaluator 預設仍使用 Greedy 一手選步，記為 `fixed_depth, depth_plies=1`；新增 `--strategy alphabeta --depth N` 以相同一般搜尋深度與相同搜尋選項比較兩份評分設定，Random 仍可作基準。一般深度不包含 quiescence 延伸，須同時查看保存的 quiescence 設定。Greedy 不提供搜尋節點統計，Alpha-Beta 此輪也未新增逐手節點資料，不虛構 nodes 欄位。Random 僅檢查基本能力，新舊版本都輕易擊敗 Random 後，需與穩定版本比較才能發現退步。固定時間比較尚未接入；日後整合需使用不同 budget mode。

正確性測試與棋力實驗分開：對稱性、權重開關或加總測試通過，只表示計算符合規格。少量對局主要驗證流程；棋力結論需要足夠且未用來反覆調參的驗證資料。截斷、停止與失敗不能列入正式和棋。

## 資料保存與未來自動調參

沿用現有批次資料：manifest 管雙方設定，games 管對局摘要與種子，positions 管逐手局面，replays 管走法。格式說明見 [自動對戰](自動對戰.md#批次資料規劃)。第一階段不更動通用資料 schema；實驗設定擴充需另外設計相容方式。

後續若使用 position 特徵資料，一筆仍是一個局面，所有特徵是該筆的不同欄位。保留 FEN、批次／對局 ID、ply、特徵版本與產生資料的引擎設定；訓練與驗證按整盤分組，避免同盤相鄰局面洩漏到兩邊。

自動調參目前只列為遠期候選：小範圍網格／逐項搜尋、對戰調參、依結果調整權重、較強引擎或較深搜尋的教師評分。先完成可重現的手動比較，不在新增特徵時順便建一套 ML 系統。

若以結果學習，白勝／和棋／白敗可映射為 1／0.5／0，代表白方預期得分，不等於單純白勝機率；弱玩家結果仍有偏差。不得把 material + PST 本身當標籤再學同一組特徵，宣稱因此獲得更強棋力。未完成對局不能硬給和棋標籤。

## 舊 ML 移除驗收

- 移除舊程式、模型專屬 CLI 選項、專屬測試與可確認的模型／指標產物，不保留舊 ML 相容別名。
- 保留 Random、手工評分、搜尋、UI、通用資料生成及回放；不刪批次、棋譜與逐手資料。
- 依 import 與執行流程盤點依賴，只移除已無其他用途的 ML 依賴宣告／文件，不為此批量卸載共享環境套件。
- 調整 engine_match 的 Random 基準入口，保留 material 的既有意義；驗證正常選項可執行，舊 ml 選項明確被拒絕。
- 更新混合測試，保留其中非 ML 的對局、截斷與儲存驗證；完整測試通過後建立獨立 commit。

## 執行方式與狀態

P5 提供兩份設定比較 CLI；下例用穩定預設與 PST 0.5 的**未驗證流程範例**跑一組交換黑白短局：

```powershell
& "./.venv/Scripts/python.exe" -m scripts.compare_evaluations `
  --baseline-config configs/evaluation/stable.json `
  --candidate-config configs/evaluation/example_pst_half.json `
  --max-plies 12 --seed 42 --name "PST 0.5 流程檢查" --tag smoke
```

若只檢查基本能力，可將 `--baseline-config ...` 改成 `--baseline-random`。可重複提供 `--initial-fen`，並用 `--repetitions` 控制每個局面的配對次數。輸出位於新批次目錄，`comparison.json` 是比較摘要；截斷列為 unfinished。完整跑到棋規終局時省略 `--max-plies`，但少量結果仍不得當作棋力證明。

P1–P5 功能已完成；自動調參仍是遠期候選。一般對戰與回放的可用命令見 [README](../README.md#快速開始)。


## Alpha-Beta 固定深度比較

2026-10-06 完成 API／CLI 整合。兩份評分設定使用同一 ComparisonSearchConfig，若策略、深度或其他搜尋選項不同，API 會在建立批次前拒絕，以保持評分比較條件一致。Random 基準不使用 evaluator 或搜尋設定。

```powershell
& "./.venv/Scripts/python.exe" -m scripts.compare_evaluations --strategy alphabeta --depth 2 --baseline-config configs/evaluation/example_king_safety.json --candidate-config configs/evaluation/example_coordination.json --max-plies 12 --seed 42 --name "E5 AlphaBeta 流程檢查" --tag smoke
```

Alpha-Beta 預設 depth=2、quiescence_depth=4、排序／TT／PVS 啟用、aspiration_window=1 pawn；可用 `--quiescence-depth 0`、`--no-move-ordering`、`--no-transposition-table`、`--no-pvs`、`--no-aspiration` 停用，或 `--aspiration-window 0.5` 調整正有限視窗。這些參數對兩方相同；Greedy 不接受搜尋參數，僅允許 depth=1。`--time-ms` 不接受，固定時間另立階段。

manifest 與 comparison.json 的 comparison schema v2 保存雙方實際 evaluator 設定、搜尋快照及一般深度預算；搜尋快照包括規則的 claim_draw、quiescence 與各開關。每盤實際建構玩家後先比對快照，若不一致則失敗並保存 failed manifest；不會把未完成對局算和棋。舊 comparison v1 與通用批次 v2 不改寫。

Alpha-Beta 同分走法依確定的搜尋順序選擇，不使用 pair seed；若基準為 Random，種子仍控制其走法。每個 pair 重設相同 seed，交換黑白及初始局面安排不變。固定深度與完整設定可重現走法，但耗時不是可重現門檻。

功能測試證明選步／保存流程；上述短局仍只檢查流程。要評估 E1–E5，固定搜尋設定，逐項比較、事先決定局面集並另外使用獨立局面驗證，正式報告勝和敗、unfinished 與耗時，不把少量短局當作棋力證據。

- 雙方 AlphaBeta 一般深度 2、quiescence 4、排序／TT／PVS 啟用、aspiration 1 pawn；workers=4、base_seed=10000、每局面一組交換黑白配對、不設手數截斷、不自動申請和棋。既有棋規判定終局，每場搜尋單執行緒。
- [觀察組](../configs/openings/e1_round1_observation.txt) 與 [獨立驗證組](../configs/openings/e1_round1_validation.txt) 各 8 個，共 32 局；依常見開局走法至第 5 回合黑方走完，涵蓋不同兵形、發展及交換。盤面、輪到方、易位權與有效吃過路兵資訊均檢查無重複，不以回合數變更冒充新局面。選取方式、SAN、FEN、完整設定、程式版本與檔案 SHA-256 固定於 [實驗設定](../configs/experiments/e1_round1.json)，不得依結果替換。
- 使用 UI 的 EvaluationFields 解析同一設定，再透過共用 `start_batch("evaluation", ...)` 派發；有限流程檢查先用兩個觀察局面、手數上限 2，僅核對多程序、配對、保存及回放，不納入棋力結果。正式批次不設上限。
